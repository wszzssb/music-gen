## 4. 本轮改掉的两处（都有实测证据）

1. **melody 层双触发**：自动接续原来没传还原模式的 `--no-melody`，于是 melody 层是 Piano 轨高音区的副本 ——
   实测 **340/340（100%）与 Piano 轨同刻同音**（PITFALLS 255 ③ 那个病：同一个音两条轨同时响）。
   已修 **标准入口**（`transcribe_ymt3.py` 的接续链现在自己传 `--no-melody`）+ 加守卫
   `t_ymt3_restore_mode_wired`（读源码 + 注入用例）。修好后重跑，`song.json` 与我手工修出版
   **逐字节相同**（sha16 `96dd62bdb1587456`，349612 字节）。
   ⚠ 这同时消掉了"旋律强拍贴合 60%"那条**假警报**（它量的是那条副本，不是编配本身）。
2. **判据崩溃**：`chord_names_match_notes` 遇到 `render.json` 里 `"composer": null`（`make_song`
   对 song.json 型曲目写的就是这个）会 `TypeError: argument of type 'NoneType' is not iterable`，
   把合法曲目判成"数据契约未通过"。已修（`c.get('composer') or ''` + 类型判断），并配了反向变异用例。
3. 入库三件套：`song.json` + `compose.py` + `notes.md` + `render.json`（composer 指向本目录
   `compose.py`）——⚠ `make_song` 只保留已有的 composer、**不会自动补**，每次重渲染后要再确认。
