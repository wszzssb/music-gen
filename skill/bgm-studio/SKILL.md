## 0. 环境（必须）

`$py = <仓库>\.venv\Scripts\python.exe`（numpy/soundfile/ffmpeg）。系统 python 3.14 无 numpy。
路径全绝对 + 编码兜底 → 任意目录可调。**长曲后台跑**。

## 1. 写一首新歌（唯一路径，别自创）

**模板依据是硬规矩**：一次生成依据**同主题 ≥8 首模板**，模板只能是 `refs/midi2/`（带来源 URL）
或网络权威数据 —— 不许拿"自己做的曲子 / 某份音频"当模板（老 `--from` 会被 `check_song` 拦下）。

```powershell
& $py ...\scripts\theme_pack.py <主题>       # ① --list-themes 看主题；同主题不足 8 首加 --allow-fetch
& $py ...\scripts\new_song.py <NN_名字> --theme <主题> --ref <画像名>   # ② 出 song.json + 旋律
#   → 只改 songs\<NN_名字>\song.json（chords / melody / sections）—— 不写代码
& $py ...\scripts\make_song.py <NN_名字> --check    # ③ 先 2 秒查数据，再作曲+渲染+调参+成绩单
#   数据错会被拦下：可先 `check_song.py <曲> --fix`
```
（`--ref` 省略时取**主题包里的混音目标**——与模板依据是两回事；改现成的歌才用 `--from`。）

## 2. 开工前先定这几件事（不定就会返工，每条都是实测踩出来的）

**−1. 开工先把两件事做掉**（用户 2026-09-16 要求）：
   · **`audit.py`** 拿"偏差项清单"（四层一次跑完，逐项"达标/偏差/**测不到**"三态；
     参考线与 **8 条必须人耳**的项 → `docs/AUDIT-CHECKLIST.md`）。
   · **音乐任务都要开 studio 面板** `http://127.0.0.1:8765`（写歌/改歌/扒谱/分析/体检/
     对比/混音都算）—— **"看一眼/听一下/试一版"的唯一入口**。**硬形式（可自查，
     2026-09-18 第二次犯同样的错之后定的：BGM35 那轮一次没用，这轮重写 16 首又全走 CLI）**：
     ① 动手前先 `curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8765/`，
        非 `200` 就先 `studio\start.cmd`；
     ② **改一版 → 面板 ⚡试听本段（1~3 秒）定方向；定稿才 CLI 整曲渲染**（整曲 18~40 秒，
        差 ~120 倍）——"改一处 → 整曲渲染当探针"就是违规，可自查；
     ③ 曲目要**挂进曲库**面板才看得见：`cmd //c mklink //J <曲库>\<曲> <真身>\<曲>`
        ⚠ MSYS 的 `ln -s` 对目录是**复制**（实测白占 460MB）。
     时机与用法 → `docs/STUDIO-WORKFLOW.md`。
   ⚠ **测不到的不许拿分数冒充**（`similarity.py` 六轴全是时间平均统计量；
   补完力度后**总分只动 0.1**）。

0. **首要标准：和谐、不突兀**（用户 2026-09-15 定）—— **优先于 CLAP happy 这类好听度指标**。
   实测教训：为把 happy 0.44→0.55 换上颤音琴，用户立刻听出"有个乐器慢半拍"。
   已量化的两种突兀：**轨间失衡**（`t_track_balance`：伴奏不许盖过旋律）、**主奏起音滞后**
   （`t_lead_timbre_attack`）。⚠ **对比本身不算突兀，但转变要有交代**（用户："有转变可以，
   但要过渡自然或中间有空白作为间隔"）：段间质心跳变中位 31% 属正常（`probe_sections_jump.py`），
   **但每个段界必须"渐弱/渐入 ≥4dB"或有留白**（`t_section_transition` 在守；
   `patterns.section_gap` = 段末渐弱到 0，实测加之前 **27/34 首硬切**）。
   **改音色/编配前先问"会不会让哪轨冒出来"。**
   **混音不是瓶颈**（我们 vs 权威 50 首的分布几乎重合；**别拿单首下结论**，
   0.39–0.66 都是商业水准）—— **真正的差距是「同质化」**：权威 RMS 跨度 4.8dB /
   质心 1858Hz，我们只有 **1.6dB / 914Hz**。三条可迁移共性（**有极静段 ·
   收尾逐小节渐弱 · 调式色彩明确**）与全部实测数据 → `docs/CASE-BGM35.md`。
   ⚠ **指标不许当差评依据**：BGM36 CLAP tense **0.961**、AQA CE 只有 7.1，用户却认为很好。

1. **调性**：`melody_profile.py` 音级直方图；`analyze_bass` 根音整体偏低半音、
   画像 tonic 只是假设 —— **判错=全盘返工**。
2. **引子**：画像 `structure` 里**引子响度≈A 段就别做稀疏引子**（占用率会掉到 66/61/79，例曲 95+）。
3. **结构化参数一次定齐再渲染**（每多一轮 = 2 分钟 + 一次成绩单）。速查 `docs/SONG-FORMAT.md`。
4. **改过 `song.json` 必须重作曲**（`--no-compose` 下 MIDI 不重生成 → 白跑一轮）。
5. **验"加这层有没有用"先用 `layer_exp.py` 离线叠层测**。
6. **速度是"层级"不是单值**（60/75/80 ↔ 120/150/160）：`check_audio.py` 报两层支持度，定参考曲
   用 `--bpm` 钉死一层记进画像，否则一路假报"速度差 100%"；连奏编配**必须**手给。
7. **像不像看「段间对比」而非整体亮度**：`analyze_sections.py <参考曲>` →
   `new_song.py … --from-sections`（全曲一条直线 = 亮却闷）。
8. **还原/扒带任务**（用户 2026-09-15 要求"统一的判断标准"）——
   ⚠ **第 0 步（用户 2026-09-17 定）：先确定识别准不准，再谈别的工序。**
   转录错一个八度时带差/EQ **照样会变好** —— BGM29 实测：低音补到 1416 音、带差 2.61→**0.83dB**，
   而那批音里 **25.3% 弹的是错八度**（一致率仅 48.5%）。
   · 量 `transcribe_audit.py <参考分轨.wav> <我的.mid> --tracks "Bass"` → **一致率 <70% 先修识别**
   · 修 `bass_ensemble.py --octave-ref <参考bass分轨>` → **48.5%→69.9%**、八度错 **25.3%→2.3%**
   · 链 `imitate_ref.py`（九段；第 9 段 = **①识别体检 → ②逐带体检**）
   · ⚠ 复音层不能用 pyin 量（那是方法假数）；⚠ **集成修不掉系统性错误** → 要**独立方法**当尺子
   细节 → `docs/CASE-BGM35-FINDINGS.md` 41 条。
   然后才轮到：**开工先跑 `audit.py` 拿偏差清单**，再改（`docs/AUDIT-CHECKLIST.md` 有全部参考线）：
   `audit.py <参考音频> <我的音频> --bpm N --mine-json <song.json> --midi <我的.mid>`
   六轴里 **`chord`/`grid`/`density` 属"照抄即可"**（做不到是方法问题，别推给音源），
   倍频程/音色/段间变化受音源与混音限制。顺手的分项判据：
   · **和弦读 `song.json`、不要重扒**（重扒对 `m7↔7`、`sus4↔7` 只有 ~39% 分辨力）。
   · ⚠ **分数≠像**：六轴全是时间平均统计量 —— 补完力度（3038 个音从"全 84"变真实动态）
     **总分只动 0.1**。**测不到的 8 条**（起音摇摆/连奏/踏板/演奏法/音色/好听度/过渡/整体）
     交付时必须逐条说明"没验证什么"，不许拿分数冒充。
   ⚠ **但也别一律归给音源**：实测某曲 160Hz–18kHz 曾低 **5–13dB**（80Hz 以下却 ±1dB），
   根因是**编配把中高频关掉了**（`arr_sparse` + 低密度档关 strings/arp/glock）；
   补 800Hz 以上 +6dB 后平均差 **6.75 → 1.87dB**。整条频谱**成片**倾斜才用
   `band_match.py <我的> <参考> <输出>`（**孤立一两带**差得多是编配问题）。

9. **"听着乱/控制不住"先量三件事**（`docs/MAKE-IT-SOUND-ALIKE.md`）：同时发声的**乐器数**
   （>4~5 件=堆叠）· **逐段每小节音符数**与原曲的相关系数 · 鼓的**逐段活跃度**；
   说"不好听"另量旋律形态：密度 2.0~2.6、末落点≥8 格 ≥65%、重复率 ≤45%（坑 127）。
   典型失控：鼓用全曲平均（不跟段落呼吸）· 扒谱把**泛音**当独立音 · **力度全平**
   （`notes_extra` 曾硬编码 84；原曲同声部跨度 24~54dB）· `melody` 写了**全局**小节号
   （引擎要**段内** → 旋律轨静音且不报错）。

9b. **改必须分段，不准一刀切**（用户 2026-09-17 定）：引擎**每层都是分段**的 ——
    `arr` 每段一套开关 · `notes_extra[轨].target` **逐段数组**(26) · `melody_prog`/`perc_target`
    逐段 · `drum_grid.per_bar` 逐**小节**(208)。用户反馈**永远指向局部**（"开头乱"/
    "110s 像"）→ **先定位到段/小节再改**，改完出**逐轨×逐小节**表核对（范例 `b35_intro_who.py`）。
    反例（都被否）：`glock_oct` 一刀切 22 段 ✗、`instrument` 一次换全轨音色 ✗。坑 163。
    ⚠ **改 `song.json` 前先确认基准**：同曲可能有多份（活跃副本 vs 过时副本），拿错会
    **静默覆盖成果**（症状="你怎么更差了"）；覆盖前记 **SHA256**、恢复**按指纹**比对、
    **别叠加后处理**。坑 162（含 BGM35 两份路径）。

9d. **听感是唯一判据 → 用「消融实验」代替猜**（2026-09-17，BGM35 十轮教训）：
    我在 BGM35 上连造 **7 个坏读数**（CQT 谱峰当音数 · 音符数/秒当起音率 · 逐帧 onset 包络
    相关 · CQT 音高重心 · 模板时间轴线性移植 · `section_gap` 当主因 · CENS 帧率换算），
    **每次都据此做出方向性错误决定**，每次都是靠"与用户认可的版本对照"才发现。
    → **不要再用自造指标猜方向**。改成：**把每项改动拆成独立版本，让用户逐个判断**。
    做法（`b35_ablate.py` 可参照）：
      ① 基线 = **用户认可的版本**（本例 `song.json.pre_r2.bak` → `v17pure.mid`）
      ② 用 JSON diff 列出"我相对基线改了哪些项"（arr 开关 / mix CC7 / drum_grid.per_bar /
         notes_extra.target / programs）
      ③ **每项单独生成一个 MIDI**（`v17_base` / `v17_pad` / `v17_drums`…）
      ④ **必须核对基线**：`v17_base` 的 SHA256 要等于认可版本（本例 `9D1E62DA…` 逐字节一致），
         否则拆解本身引入了偏移
      ⑤ 用户只需说"A 比 B 好"，就能**精确定位**哪项该留、哪项该扔
    ⚠ 新指标**必须先拿认可版本自检**：若它在认可版本上给出"差"的读数，那是**指标错**。

9c. **别用频谱指标判断「像不像」**（2026-09-17 实证，最贵的一课）：
    把用户认可的模板 `BGM35 (1).mid` **自己渲染一遍** —— 质心 **1035**（参考 3522）、
    平均带差 **14.11 dB**、10000–18000Hz 差 **−47.9 dB**；而我的版本是质心 3973、
    带差 1.04 dB —— **频谱"更对齐"，但用户认可的是模板**。
    → **判断像不像只看音符层**（音高集合 / 密度 / 织体 / 起音 / 力度）；
    `band_match` / 质心 / 带差是**成品音频的混音工具**，**不是还原目标**。
    ⚠ 推论：**删掉一层高音色（如鼓 + 木琴）必然让 5–18kHz 塌 30dB 以上，
    这是编制的物理结果，不是缺陷** —— 别拿它否决编制方案。坑 165。

## 3. 会改变行为的这几条（其余按需查文档）

1. **别手开"渲染→测→调"循环**：`make_song` 内部闭环（≤6 轮），改完最多再跑一次；
   **要改的多处先一次列全再渲**（反面教材：一首渲 6 次，4 次是"改一处→渲→看"的试错）。
2. **速度一律取自 MIDI（`--bpm`）**：连奏编配会被 `detect_bpm` 测错（106BPM→154.3），小节指标全错位。
3. 成绩单说**"已到顶 → 靠编配"**时改 `mix`/`programs`，别再推 EQ；**不许把"没达标"说成"达标"**。
4. **人声参考曲**只对齐 160–10kHz；不该追的差距写 `align_exempt` + 理由（空白理由自检会拦），
   **不许改阈值"通过"**。
5. `perc: none` 会让 5–18kHz 塌掉 → 要"无鼓组"用 `perc_style: light` + `perc: 1`。
6. **别拿 4 小节小样判断像不像**（预演只证明管线通）。
7. **全量自检只在两种时候跑**：交付前、或**改过检查项本身**（那时配 `mutation_check.py`）。
   改一行数据/编配别跑全量，只跑相关那条。**动过引擎**才要全库重跑 `make_song`。
8. 交付：`<曲目>.mid` + `_sf.ogg` + `notes.md`（调性/速度/结构/复现/**没达标项**）。
9. 汇报只给结论 + 差距表 + 一句"还没验证什么"。
10. **改编配前先量，别拿整曲渲染当探针**：`bands_abs.py` 看绝对差+占用率、
    `probe_timbre.py --solo` 看哪轨真响；A/B 用 `--no-tune`（见坑 103）。

11. **"不好听"先量形态**：见 §2 第 9 条（形态三条 + 守卫 `melody_form_rules`，坑 127）。
