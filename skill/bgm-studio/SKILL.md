## 1. 直接作曲（"来一首 BGM"）—— 新歌**两条合规路径之一**，别自创

> **另一条是「模仿写歌」**（"照着某首做 / 仿照某曲"）：依据**同样是主题模板包**，但要按**单首参考曲**
> 实测的结构（每 8 小节块起音数曲线 / 调式 / 段数）重排段落 → `docs/IMITATE-PATH.md` +
> `scripts\imitate_plan.py`。**两条都不许自创依据、不许拿"某份音频"当模板**；
> 只改 `--ref` 不算模仿（那只是混音目标）；抄音符是还原（`docs/RESTORE-METHOD.md`），不是模仿。

**模板依据是硬规矩**：一次生成依据**同主题 ≥8 首模板**，模板只能是 `refs/midi2/`（带来源 URL）
或网络权威数据 —— 不许拿"自己做的曲子 / 某份音频"当模板（老 `--from` 会被 `check_song` 拦下）。

⚠ **MIDI 模板库不入库**（版权 + 体积），**但这不影响别人 clone 下来直接写歌**：
`refs/midi2/` 只带 `_index.json`（索引 + 逐首 md5）与 `_sources.json`（来源 URL），
而**写歌读的是画像** `refs/themes/*.json`（15 个主题包 = 150 首模板的聚合，已入库），
校验时比对的也是**索引里的 md5**、不碰 MIDI 文件 —— 实测把 MIDI 全移走，
`t_theme_pack_valid` / `t_theme_basis_whitelist` 仍 PASS。只有**加/改主题**
（重算画像）才需要 MIDI：`scripts\fetch_midi_lib.py` 重抓即可。

```powershell
& $py ...\scripts\theme_pack.py <主题>       # ① --list-themes 看主题；同主题不足 8 首加 --allow-fetch
& $py ...\scripts\new_song.py <NN_名字> --theme <主题> --ref <画像名>   # ② 出 song.json + 旋律
#   → 只改 songs\<NN_名字>\song.json（chords / melody / sections）—— 不写代码
& $py ...\scripts\make_song.py <NN_名字> --check    # ③ 先 2 秒查数据，再作曲+渲染+调参+成绩单
#   数据错会被拦下：可先 `check_song.py <曲> --fix`
```
（`--ref` 省略时取**主题包里的混音目标**——与模板依据是两回事；改现成的歌才用 `--from`。）

    版本对照"才发现（七个坏尺子逐条 → FINDINGS 里那张表）→ **别再用自造指标猜方向**，
    改成**把每项改动拆成独立版本，让用户逐个判断**。
    做法（`b35_ablate.py`）：① 基线 = **用户认可的版本** ② JSON diff 列出"相对基线改了哪些项"
    （arr 开关 / mix CC7 / drum_grid.per_bar / notes_extra.target / programs）
    ③ **每项单独生成一个 MIDI** ④ **必须核对基线 SHA256**（要与认可版本逐字节一致，
    否则拆解本身引入了偏移）⑤ 用户说"A 比 B 好"即可**精确定位**哪项该留。
    ⚠ 新指标**必须先拿认可版本自检**：它在认可版本上给"差"读数 = **指标错**。

9c. **别用频谱指标判断「像不像」**（2026-09-17 实证，最贵的一课）：
    把用户认可的模板 `BGM35 (1).mid` **自己渲染一遍** —— 它的质心/带差比"更对齐"的我的版本
    **差一个数量级，可用户认可的偏偏是模板**（数字见 FINDINGS 第 6 条）。
    → **判断像不像只看音符层**（音高集合 / 密度 / 织体 / 起音 / 力度）；`band_match` / 质心 /
    带差是**成品音频的混音工具，不是还原目标**。
    ⚠ 推论：**删掉一层高音色（如鼓 + 木琴）通常让 5–18kHz 塌一大截（那轮实测 30dB 以上）——
    这是编制的物理结果、不是缺陷**，别拿它否决编制方案。坑 165。

## 3. 会改变行为的这几条（其余按需查文档）

1. **别手开"渲染→测→调"循环**：`make_song` 内部闭环（≤6 轮），改完最多再跑一次；
   **要改的多处先一次列全再渲**（反面教材：一首渲 6 次，4 次是"改一处→渲→看"的试错）。
2. **速度一律取自 MIDI（`--bpm`）**：连奏编配会被 `detect_bpm` 测错（106BPM→154.3），小节指标全错位。
3. 成绩单说**"已到顶 → 靠编配"**时改 `mix`/`programs`，别再推 EQ；**不许把"没达标"说成"达标"**。
4. **人声参考曲**只对齐 160–10kHz；不该追的差距写 `align_exempt` + 理由（空白理由自检会拦），
   **不许改阈值"通过"**。
5. `perc: none` 会让 5–18kHz 塌掉 → 要"无鼓组"用 `perc_style: light` + `perc: 1`。
6. **别拿 4 小节小样判断像不像**（预演只证明管线通）。
7. **全量自检只在两种时候跑**：交付前、或**改过检查项本身**（那时配 `mutation_check.py`）。
   改一行数据/编配别跑全量，只跑相关那条。**动过引擎**才要全库重跑 `make_song`。
8. 交付：`<曲目>.mid` + `_sf.ogg` + `notes.md`（调性/速度/结构/复现/**没达标项**）。
9. 汇报只给结论 + 差距表 + 一句"还没验证什么"。
10. **改编配前先量，别拿整曲渲染当探针**：`bands_abs.py` 看绝对差+占用率、
    `probe_timbre.py --solo` 看哪轨真响；A/B 用 `--no-tune`（见坑 103）。
11. **分钟级步骤先报"在做什么 + 预计多久"**（用户 2026-09-20 定）：分轨/转录/集成/精修
    这类分钟级工序，**开工前一行说明「在做什么 · 约多久 · 出什么」**，别静默跑完再报 ——
    实测被追问"怎么这么慢，以为卡住了"（同一首曲子：全混音转录 22 秒 vs 10 条分轨 6 分钟，

12. **单乐器（尤其纯钢琴）/ 抒情类新曲：先读案例 + 量公认模板，再动 `song.json`**

    ① 钢琴别开 `arr.pad`/`arr.strings` —— 垫子层时值 4.1 拍，钢琴音色下听感是
       **"音符延长得太奇怪"**（`check_song` 会提示）
    ② 和弦用**密集三度叠置**（开放排列 = 空洞），且改完必须校验**音级完整性**（坑 216）

       换成 32 + 引子不用 bass；守卫 `t_bass_timbre_is_low` 守着（全库 30 首现均合规）。
13. **"不好听"先查旋律，不要先查响度 / EQ / 宽度 / 频段**（用户 2026-09-21 明确定，**默认判据**）。

14. **交付物与曲库是两回事**（用户 2026-09-21 实测报错后定）：**交付目录放曲库外**

15. **"不和谐"先量三项，别先凭感觉挑和弦**（用户 2026-09-21"感觉不是很和谐"）——
    实测根因**一条都不在和声写作上**（强拍和弦贴合 100%、0 条错音）：
    ① **旋律↔和弦音区间距**：应在 **5–22 半音**（正统钢琴 = 旋律在中音区、左手在其下方
       一个八度左右）。我做成 **21–34**（旋律漂到高音区、和弦沉到低音区，中间两个八度全空）
       → 听感"空 + 高音发尖、跟伴奏不融合"。
    ② **跨轨同刻同音高（撞音）**：两条同类音色轨弹同一个音 → 音源发浑。实测 **148 处**
       （Arp 与 Hook 音域完全重合、最常见音高都是 64）→ 抬八度或砍轨，降到 **28 处**。
    ③ **长音层**：`Pad`/`Strings`（4.1 拍）与 `shimmer`（塞在 Arp 轨里的 4 拍长音）—— 钢琴
       这类"靠衰减"的音色按住不放就是不和谐。判据与量法见 `PITFALLS.md` 219。
16. **"嘴替"只能报「离群量」，不能报「问题」**（2026-09-21，全库实测）。
    **阈值型判据在本库基本失效**：审计 30 首 —— 撞音 **32/30 首恒真**、音区 39/30 近恒真、

    撞音 498 处、比我们多"—— **方向与听感相反**。撞音消融 A/B 用户听 **"差不多"**。
    → **报"有问题"必然是噪声**（用户特意要求加的"和谐检查"实际等于没查，见 `PITFALLS.md` 225）。
    **正确形态**：报**离群量** ——「小步率 **11%**（全库中位 **20%**）→ 跳进偏多 →
    *听起来会不够连贯*」。**不依赖任何阈值**、每个数字都实测、模型编不了；
    用户也不需要知道标准，看到"偏低/偏高"就知道方向。
    **判读口径**：触发率 100% = 噪声 · 0% = 空转 · 5%~30% = 有区分度。
    量法：`scripts\selfcheck.py <曲目>`（单曲 → 人话离群清单）。
    要"让模型听"见 `docs\AUDIO-CRITIC.md`：**能定位"哪段可疑"、不能判"这版比那版好"**，
    且默认 greedy 才可复现（那一块的全部内容都在那份文档里）。

17. **"不好听"里有两类要分开量：音色的「持续能力」与短音的「力度」**（用户 2026-09-22，两轮才定位）。

    **判据在 `harmony_check`**（`check_song` 与 `make_song` 每轮都跑，不用记）；

    ⚠ 音频包络只能**量**一个音、**不能数音的个数** —— 数错会把真凶安到别的轨上（实测白走一轮）。
    全部实测数字与两条坑 → `PITFALLS.md` **235 / 236**。

## 5. 已知天花板

GM 音源（GeneralUser GS）不如商业库 —— **MIDI 才是上限最高的交付**。
底鼓采样 0.14~0.18s → 连续性靠 `perc_layers`，瞬态补不了。和弦识别用 `probe_peaks.py`（谱峰法）。
**扒谱的天花板在模型输入端**：YourMT3 的 `f_min=50Hz / f_max=8000Hz` 写死在权重配置里 →
20–40Hz 的 sub-bass 与 8kHz 以上的细节**物理丢失**（kick 垫层实测只值 ~1dB）；
用户说"开头没原曲复杂"时**先量起音事件密度**（EQ 只修频谱、修不了事件数）
→ 数字与判据见 `docs/RESTORE-METHOD.md` §2b。
**扒谱开工前先过一遍 `docs/RESTORE-METHOD.md` §10 防错清单**（6 条，全是一次会话里真踩的：
同模型自证当精度证据 · 绕开引擎正路 · 归因跳步 · 尺子没自检 · 工具静默失效 · 一刀切）。
