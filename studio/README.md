# BGM Studio —— 可视化面板（引擎面板 + MIDI 编辑器）

**位置**：`<music-gen>\studio\`（就是本仓库的一个子目录，一切都在同一个文件夹里）。
驱动的是**本仓库自己的脚本**（`scripts\*`），面板不重写任何音频逻辑：改的永远是 `song.json`，
所以面板与 CLI（`make_song.py`）两条路结果一致。

**而 CLI 现在默认就走面板**（2026-09-19 起的 A′「面板是唯一入口」）：手敲 `new_song.py` /
`make_song.py` 会把任务**委托给面板 API**（`/api/new`、`/api/job?kind=render-tune|render`），
于是任务在 GUI 里全程可见、产物立刻能听。这是被"同一条规矩**文档写了四遍、用户当场问了五次**
仍没执行"逼出来的：规则不落成代码就不算规则。两个开关 —— 面板自己调脚本时带
`BGM_STUDIO_INNER=1`（走原生实现，**防递归**：`/api/new` 背后正是起 `new_song.py`）；
批量 / CI 用 `BGM_CLI_DIRECT=1` 直连（面板无等价任务时，如 `make_song --check`，也自动不委托）。

**两个页面**：`/` **引擎面板**（下表全部能力，面向"做一首自己的曲子"）；`/editor` **MIDI 编辑器**
（导入任意 `.mid` → 卷帘编辑 → 导出，面向"编辑标准 MIDI 文件"；对标 miditoolbox 的功能面，
另多出"把成品接进引擎渲染与体检"这一步）。

## 启动 / 停止

```powershell
studio\start.cmd          # 双击也行：起服务 + 开浏览器（已在跑则只开）
studio\stop.cmd           # 按端口杀进程树
# 手动：<仓库>\.venv\Scripts\python.exe studio\server.py --port 8765 [--open] [--root 曲库]
```
`http://127.0.0.1:8765`，只监听本机。交付物默认导出到 `<仓库>\export\<曲目>\`。

## 它能干什么 ↔ 背后是哪个工具

| 能力 | 面板操作 | 背后 |
|---|---|---|
| 按音轨制作 | 音轨卡：GM 音色号 / CC7 / 声像 / 音符数；段落里逐轨开关 + 逐段 CC7、力度 | `song_engine` 的 `programs/mix/arr` |
| **实时混音台** | 「⬇ 载入分轨」→ 分轨同播，推子/声像/静音/独奏/电平表；「↩ 写回」；「🔊 以当前混音渲染」 | `bridge stems` + WebAudio |
| **⚡ 试听本段** | 只渲染**当前段落切片**并循环（实测 1~3 秒）：改一版立刻听 | `tools/preview_job.py` |
| **🎚 自动配平** | 解方程求每轨 CC7（±6dB 护栏）→ 真渲染 → 实测成绩单 → 更好才留、更差回滚；限幅时给"该改哪一轨" | `bridge mixfit` + `tools/mixfit_job.py` |
| **🧬 候选搜索** | 选段 + 速度档 → 切片渲染 + 多路并行 + 贪心搜索；出**逐项采纳表**（织体类预勾选、性格类标红），**默认不写回** | `tools/search_job.py` |
| 可视化写旋律 | 卷帘：全轨着色；**Melody 可增删拖**、拖右缘改时值、Alt+拖改力度；**和弦内音导引带 + 强拍违规描红** | `scripts\song_events.py` + `song.json` |
| 段落/和弦编辑 | 选段 → 小节数 / 每小节和弦 / 编排开关 / 混音；「🎹 和弦表」改和弦定义（实时校验） | `song.json` 契约 |
| 指标 | 绝对倍频程差 + **占用率**（墙/点）+ RMS/宽度/质心；可按**时间窗**（引子/安静/主体/尾奏） | `bridge metrics`（同 `bands_abs.py` 口径） |
| 参考曲 A/B | 传输条切「主混音 / 分轨混音 / **参考曲**」，同位置、同循环区间 | `/api/ref-audio` |
| 播放/循环/波形 | 波形拖动定位，Shift+拖设循环，播放头走独立叠加层 | `engine.js` |
| 作曲/渲染/调参 | 🎼 作曲 / 🔊 渲染（+宽度校准）/ ✨ 渲染+调参（自动 EQ） | `song_engine` / `make_song.py` |
| 合并/分轨导出 | 📦 合并交付（MIDI+OGG+WAV+notes+song.json）/ 🎚 分轨（`stems/*.ogg`） | `bridge export` |
| ➕ 新建曲目 | 脚手架：选**主题模板包**（同主题 ≥8 首白名单模板）+ 频谱画像 | `new_song.py --theme` |
| 保存/校验/撤销 | 💾 规范写回 · ✅ 数据契约检查 · Ctrl+Z/Y（含音符级） | `json_io.py` / `check_song.py` |

## 卷帘 / 波形交互

| 操作 | 行为 |
|---|---|
| **点段落条** | 跳到该段开头：位置 + 视窗 + 红线一起走，红线落在**正中** |
| **播放中** | 红线**居中跟随**：视窗起点 = 播放拍 − 跨度/2，被 `[0, 总拍−跨度]` 收口 —— 开头半屏从左走到中、中段钉在正中（连续滚）、结尾半屏再走到右 |
| **卷帘上滚轮** | 一律**不滚整页**（`preventDefault`）：Ctrl+滚轮 = 缩放 1~16 倍；普通滚轮 = 横移视角（含触控板 `deltaX`） |
| **手动横滚后** | 播放中的跟随**让位 2.5 秒**（回看一眼不会被每帧拉回正中），随后自动恢复 |
| **拖进度条 / 点波形** | 红线**即时重画**（不等下一帧）；落进视野外时视窗跟过去 |

⚠ **zoom=1（默认整曲视野）时视角无处可移**：整曲已在卷帘里，视窗起点被收口到 0，红线速度是
"整曲秒数铺满 ~900px"的必然（331 秒的曲子实测 **≈2.7px/s**）—— **要看画面持续滚动，先 Ctrl+滚轮放大。**

这套行为挂在 `app.js` 的**常驻 rAF 循环**上（加载即启动 + 防重入）；它原来只在点 ▶ 时才启动，
于是"暂停态拖进度条"会波形动、红线不动（已修，`0d8a8c9`）。

## 速度（本机实测）

| 动作 | 耗时 |
|---|---|
| 候选搜索单次渲染 | **0.36 s**（8 小节切片；150BPM 歌） |
| 搜一轮（标准档 48 次预算 / 4 路并行） | **11 秒**（慢歌 67.6BPM 切片更长 ≈60 秒） |
| ⚡ 试听本段（4~8 小节） | **1~3 秒** |
| 整曲渲染（含宽度校准） | **18 秒**（238 秒的歌）~40 秒 |
| 整曲渲染 + 自动调参 | 2~3 分钟（只在定稿跑） |

速度靠三件事：**只渲染切片** + 多路并行 + 渲染预算/墙钟上限/⏹ 停止。

## 边界（诚实）

- **只有 Melody 轨能手写音符**，其它轨由引擎按和弦+编排生成（改和弦/开关/CC7 才是正确改法）。
- 混音台推子是线性增益，写回按 `CC7 = gain×100`；**写回后要重新渲染**才进 MIDI/成品。
- 🧬 搜索适应度只衡量"更像参考曲"，不衡量音乐性 → **性格参数（律动/移调）必须人工确认**（默认不写回）。
- 指标只证明"像不像"，**好不好听只能靠耳朵**；10-18k 的"连续空气墙"是音源天花板（坑 103）。
- 中间产物（分轨缓存/切片）在 `%TEMP%\bgm-studio-audio\`，不进仓库；**启动时按预算自动清理**
  （`prune_tmp_audio`：>7 天的删、总量压到 512MB，最旧先删；`--keep-tmp-audio` 跳过）——
  以前从不清理，实测涨到 0.93GB（坑 125）。

## 中英切换（右上角 🌐）

右上角 `🌐 EN` / `🌐 中文` 开关，点一下切语言并刷新。**首次按系统语言自动判**（`navigator.language`），
选择存 localStorage。

实现是「**中文就是 HTML 原文** + 按字典替换」（`web/i18n.js`）：切英文时逐节点换成英文，切回中文
只需刷新 —— 不用维护两份 HTML，也**不动** `engine.js` / `app.js`；它们运行时写进 DOM 的文案由
MutationObserver 兜住。

覆盖面与缺口（**有脚本守，别凭印象**；静态文案现 **153 条** = index 76 / ed 77）：

| 类别 | 状态 |
|---|---|
| 静态文案（HTML 文本 + `title`/`placeholder`） | **全覆盖**，`i18n_check.py` 守（漏一条退出码 1）—— 漏翻**只有英文环境看得见** |
| 运行时文案（音轨卡 / 曲目下拉 / 段落条等） | 已翻，走 `i18n.js` 的 `DYN` + `REGEX` 表（失配只退回中文、不报错 → 改 `app.js` 模板时回来对一眼） |
| 日志整句、canvas `fillText` 的字 | **仍未翻**（要改 `app.js`/`ed.js` 本身）；`smoke_i18n.js` 单独列它们，实测此外**零汉字残留** |

## MIDI 编辑器（`/editor`）

一份**可编辑的 MIDI 模型** + DAW 式界面，导入**任意标准 MIDI**（Type 0/1、`.mid/.midi/.kar`；
拍号 2/2、3/4、6/8 都支持）。

| 能力 | 操作 |
|---|---|
| 加载 | 默认**只读**（`🔒 只读`）；右上角切 `✏️ 编辑中` 才能改 |
| 钢琴卷帘 | 拖=移动 · 右缘拖=改时值 · 空白拖=新建 · 右键删 · 滚轮缩放 · Alt+拖=力度 · Ctrl+点多选 |
| 量化 | 网格 1/1~1/32（含三连）+ 吸附 + **强度**（<1 部分量化）与**摇摆** |
| 力度 | 力度通道拖动 · ×/+/=/夹取/人性化 · **渐变（渐强渐弱）** |
| 移调 | 半音（整轨或选中）；越界自动夹取并计数 |
| 多轨 | 独奏/静音/隐藏 · 换乐器（GM program）· 通道 · 复制轨 · 删轨 |
| 编辑 | 加/删音符 · 复制区间 · 粘贴 · 去重 · 修剪同音高重叠 |
| 导出 | Type 1 / Type 0，导出后**当场做往返校验** |
| 和弦 | 🎵 按小节识别（带置信度）· 🎼 写成和弦轨 |
| 播放 | 进度条定位 · 标尺 Alt+点定位 · 标尺拖选 A–B 循环 · 🎧 真音源 |
| 其它 | Ctrl+Z/Y 撤销 · Delete 删选中 · Q 检测和弦 / W 生成和弦轨 |

**口径**：音乐语义全在 `scripts/midi_ops.py`，前端只发 `{op, params}`、服务端用同一份函数执行 ——
"面板做的"和"自检测的"是同一件事（`midi_ops_semantics` / `midi_file_editor_roundtrip`）。

**听感（真音源）**：点「🎧 渲染音频」→ 导出 MIDI → **与引擎面板同一条 `render_midi.py` 管线**
（GeneralUser GS）渲染 OGG 并播放（123 秒约 7 秒、后台跑；改了音符才重渲）；未渲染/失败时退回
**WebAudio 合成音**（6 音色族·多泛音+滤波+混响）。两条音源共用同一套时钟语义。

**边界**：导入的 `.mid` 不进曲库（会话在 `%TEMP%`）；同音高重叠无法唯一还原配对；和弦识别是
模板匹配（和弦音被省略时会差一个音）；**还没有** 键盘录制、CC 曲线编辑、弯音轮导出。

## 创作台（`/create`）—— 给"自己点着用"的入口

**双击 `studio\创作台.cmd`**。它是**桌面窗口版**：`pythonw` 跑 `studio\desktop_app.py`，
由 `pywebview` + 系统 **WebView2** 开一个**原生窗口** —— 没有地址栏/标签页，任务栏上是它自己的
标题，**不经过 Edge**。关窗即退出，且**只停"自己起的那个服务"**（复用别人已开的实例时不动它）。

| 件 | 作用 |
|---|---|
| `studio\desktop_app.py` | 窗口壳：socket 探活 → 没服务就起一个（`CREATE_NO_WINDOW`，不弹黑窗）→ 开窗 → 关窗停服务。`--selftest` 只体检环境不开窗；⚠ 异常写 **`%TEMP%\bgm-studio-desktop.log`**（`pythonw` 下报错是看不见的，所以必须留档） |
| `studio\创作台-浏览器窗口版.cmd` | 兜底：老的 Edge `--app` 模式（WebView2 或 pywebview 不可用时用） |

依赖：`pywebview`（已装进主 `.venv`，连带 `pythonnet`/`clr_loader`/`bottle`/`proxy_tools`）
+ 系统 **WebView2 Runtime**（`python desktop_app.py --selftest` 会报在不在、报的哪个版本）。

⚠ **"窗口开了但整片白"的排错**（2026-10-07 实际踩到，截图确认）：那是 WebView2 Runtime
**残缺** —— 本机当时注册表写着 `142.0.3595.80`，而那个版本目录里**根本没有 `msedgewebview2.exe`**
（只有 `SetupMetrics` 之类的残留）。pywebview 这时**不抛异常、只打一句日志**，
所以"窗口出来了"**不能**当成成功（我第一次就是这么误判的）。

```powershell
python studio\desktop_app.py --selftest                  # 看 WebView2 Runtime 那行报的版本
winget install --id Microsoft.EdgeWebView2Runtime        # ⚠ 要**管理员**：--scope user 实测装不上（报成功却没落地）
```
装完：注册表 `pv` 变新版本、版本目录里出现 `msedgewebview2.exe`、`--selftest` 报新版本，
窗口即正常渲染。`desktop_app.py` 另有两道保险：**开窗前先查注册表**（查不到就弹窗说明 + 降级到
浏览器窗口版），以及**看门狗**（20 秒内发现 pywebview 报初始化失败 → 关掉白窗、换 Edge 应用模式）。

⚠ 后端**仍是本地 HTTP 服务**（`server.py`）：面板的前端、引擎调用、后台任务、音频流都围绕它的
二十多个路由。换成原生窗口只是**换外壳**，不是把后端搬进进程内 —— VS Code / Slack / 微信桌面版
也都是"外壳 + 内嵌浏览器内核"这个形状，区别只在外壳是不是浏览器进程、有没有浏览器 UI。

⚠ **双击没反应时**先看 `%TEMP%\bgm-studio-launcher.log`：启动器全程写日志（开始 / 端口是否
已在监听 / 起服务 / 等了多少秒 / 找到哪个 Edge / 退回默认浏览器），一句话就能分清是"没等到端口"
还是"没找到 Edge"。⚠ 改启动器时**别用 `for %%P in (...)` 收集候选路径**：`%ProgramFiles(x86)%`
展开后带 `)`，会把集合提前闭合，cmd 报语法错误后**整个批处理静默中止**（退出码仍 0、无输出、
不起服务也不开窗，2026-10-07 实测白查一轮）—— 用 `if exist` 链。

| 区块 | 干什么 | 背后 |
|---|---|---|
| ① 提要求 | 中文口语 → 生成参数（主题 / 能量 / 乐器 / 时长 / 种子），**逐项摊开可改**；解析只给建议、不直接出声 | `scripts/ask_parse.py`（纯本地规则、离线） |
| ↳ 速度 / 风格 / 时长 | 主题画像里的**实测值**直接摆在界面上：`bpm`（中位，可改）· `engine_style` · 拍号 · 总小节数 · **预计时长**（总拍数 ÷ BPM，随 BPM 实时变）。改 BPM 是**真生效**的 —— 生成时写回 `song.json` 的 `bpm`，引擎就是拿它做拍→秒换算（实测：138→180 BPM 让成品 212 秒变 165.7 秒）；说「要 90 秒」会反算出建议 BPM 并填进去，超出 50~220 就只提示、不硬填（段落结构本版不动）。⚠ **风格（引擎预设）是"跟随主题"的、不单独改**：主题路径会把音色/织体显式写进 `song.json`，单改 `style` 字段会被盖住 —— 要换风格就换主题 | `GET /api/create/themes` 带画像参数 · 写回走 `POST /api/song` |
| ↳ 导出 | 产物卡上的「📦 合并导出」→ MIDI + OGG + WAV + notes + song.json 拷到 `<曲库>/export/<曲目>/` | `POST /api/job?kind=export` |
| ② 扒谱提取 | 拖入音频 → 选两档之一 → 起任务 | 见下表 |
| ③ 任务 | 阶段 pills（按日志里的 `=== [i/N]` 点亮）+ 实时日志 + ⏹ 停止（1 秒轮询 `/api/job`） | `server._new_job` |
| ④ 产物 | 试听 + 下载 MIDI/OGG + 跳 MIDI 编辑器 / 引擎面板 | `/api/files` · `/api/dl` |

**两档提取**（都走引擎正路，不手工拼 MIDI —— 手工链会丢编配/音色/段落控制，见 SKILL §8）：

| 档 | 命令序列（`server.extract_plan`） | 产物 | 耗时（本机） |
|---|---|---|---|
| ⚡ 快速版 | `stem_split -m htdemucs_6s` → `transcribe_ymt3`（转录 → 切轨 → `transcribe_to_song --auto` → `song.json`）→ `make_song --no-tune`（作曲 + 渲染，**不调参**）→ `extract_notes.py` | `song.json` · `compose.py` · `notes.md` · `render.json` · `<名>.mid` · `<名>_sf.ogg` | **实测 60 秒**（98.8s 音频：分轨 3.9s · 转录 11.6s · 其余是切轨/和弦/编配/作曲/渲染） |

⚠ 完整还原那档为什么多一步"摊平"（2026-10-07 实测）：`probe_instruments.load_stems` 按 `h4_`/`h6_`
**前缀**过滤，而 demucs 标准输出是**无前缀**的 `piano.wav` —— 直接给标准目录，编制表会**只剩"
①②③a"层**、分轨能量证据整列丢失（probe 输出里那些 `-`），后面的 `arrange` 随之退化成"没有证据
就不改"。`extract_plan` 因此先用**硬链接**摊平一份 `stems_h6/`（失败退回复制）再交给它；
摊平后同一首曲子 probe 不再出现"只出①②③a"、`-` 列归零。

⚠ 两档都**先分轨**：`transcribe_ymt3 --stems-dir` 是**逐音力度唯一的来源**，不分轨则每个音力度恒 100
（"打字机"）。⚠ 两档最后都**必须** `extract_notes.py`：转录那条链自己不写 `notes.md`，而曲目目录要齐
4 件（`notes_present` 就是这么判的）—— 少了它，**提取出来的每一首**都会让全量自检变红（实测踩到）。
⚠ 工作目录在**曲库外**（`<工具链>/_extract/<曲名>/`，已进 `.gitignore`）—— 曲库根混进散装音频会让
`probe_lib` 把整库判成"一首曲"（§2.5）。

⚠ **快速版是"未精修"的半成品**：它不写 `patterns.velocity_exempt` / `perc_exempt`，所以全量自检里
`velocity_measured`（某轨力度仍是恒 100）与 `perc_declared_for_restore`（打击乐占比偏高）**可能点名
这首曲子** —— 那是**精修没做**（完整还原那档才做），不是提取失败；`notes.md` 里也逐条写了"没验证什么"。
