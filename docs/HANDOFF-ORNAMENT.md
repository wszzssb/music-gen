## 1. 一句话现状

- **提取侧已入库**：`scripts\ornament_probe.py` —— 给一个时间窗，它打印该窗"哪些音高在依次响"
  （逐帧谱峰 + **谐波筛**，`*` 独立基音 / `~` 疑似谐波），并在给了 `--midi` 时报"我们写了没有"。
  ⚠ 能力边界（**写在每次报告里**）：四种统计里只有"逐帧明细 + 谐波筛"可靠 —— `pyin` 置信度
  **0.01** · 整窗能量份额分辨力不足 · 按出现帧数排序会淹没快速音 · 全曲轨迹参数敏感
  （BGM35 同素材换参数候选 **52~155 处**）⇒ 清单**只当线索**；且**不是归属判据**。
- **生成侧一个字节没动**：`melody_gen.py` 现在只能写**单音**装饰 + 大跳后回填，
  **写不出 4–7 音的快速跑动**（就是 BGM35 19.0–19.6s 那种）。

## 2. 生成侧现状（代码事实，照着读）

| 已有 | 位置 | 说明 |
|---|---|---|
| 动机层（1 小节 figure + 音程 cell） | `melody_gen._motif_cell` / `_variants_of` | 移位 / 压缩 / 扩展 / 稀疏 四类变体 |
| **单音**装饰 | `_decorate_cell` + `DECOR_CELLS` | 每小节**至多一个** 16 分装饰；位置按画像 `onset16_hist` 权重抽；弱格 ~8–12% |
| 大跳后回填 | `_ir_intervals`（`GAP_FILL_P=0.55`） | Narmour 期待规则 |
| 节奏细胞（opt-in） | `apply_rhythm_cells` | `new_song` 对新歌默认开 |
| 出口不变量 | `gen_section` 末尾 | 相邻落点 ≥0.5 拍 · 不叠音 · 密度上限 2.6 音/小节 |

**缺口**：没有"**多音、短促、同向级进**"的音型，也没有"逐段不同"的控制。

## 3. 依据从哪来（**先定这个再写代码**）

项目铁律：**依据必须来自主题模板包**（一次生成依据同主题 ≥8 首模板），不许自创。两条岔路：

- **B1 画像派生**（快 · 零下载）：`refs/themes/*.json` 的 `melody` 里已有
  `interval_hist` / `dur16_hist` / `onset16_hist` / `stepwise_pct` / `density`
  ⇒ 组合出"这主题的转音倾向"（短时值多 + 级进多 + 弱格多 ⇒ 转音多）。
  ⚠ **这是派生量**，必须在元数据与文档里标明"不是直接量"，**不许**当成"模板真实转音密度"。
- **B2 重抓模板库直接量**（依据硬 · 要联网）：`scripts\fetch_midi_lib.py` 重抓 `refs/midi2/` 的 MIDI
  → 用 `ornament_probe.find_ornaments`（需**新增一档宽松参数**，见 §5-1）逐首量
  "连续级进 run 的**密度 / 音数 / 方向分布**" → 写进 15 个主题包新字段（如 `melody.ornament`）
  ⇒ 生成侧只读画像。
  ⚠ 代价：联网 + 重算主题包（`theme_pack.py`）+ `t_theme_pack_valid` / 索引 md5 / 预算。

## 4. 建议落地形态（B1/B2 都适用）

1. **新音型 = "转音细胞"**：**3–5 个音**、总时长 **0.3–0.8s**、**同向级进为主**（允许一步 ≤5 半音）、
   音高**只取该小节和弦音/音阶音**（和谐优先是用户第一条口径）。
2. **插在动机间隙，不动骨架**：动机的"落点 + 时值"不改，只在两个落点**之间**替换/细分
   （例如把一个 1.0 拍的音拆成 4 个 16 分）。
3. **逐段决定**：每段独立判"该不该有、有几个"（按该段自己的画像/密度）—— **不是整曲一刀切**。
4. **跨曲/跨主题不同**：音数/方向/位置由**该主题画像 + 曲名派生种子**决定
   （同族纪律：`--seed` 会被"多首显式同一个 seed"抹平，`PITFALLS` **304**）。
5. **出口不变量不许破**：改完 `gen_section` 出口那两条会**当场炸**（这是设计）。

## 5. 验收判据（缺一条不算完）

1. **工具侧先标定**：`ornament_probe` 目前的能力边界全部来自 **BGM35 真实混音**，
   **没在生成曲（GM 渲染、编配干净）上标定过**。第一步是拿**合成件/已知答案**跑一遍：
   生成曲上它能不能分开"有转音/没转音"；不达标就先给它加一档宽松参数（`WIDE`）并重标。
2. **隔离基线**：`melody_gen --dry-run` 先出改前统计（密度 / 落点 TVD / 碎音率 / 级进率），
   改完逐项对比，**不许凭感觉**。
3. **A/B 让用户听**：出"有转音 / 无转音"两版（**同 seed、只差这一个维度**）——
   **听感赢**，用户说不好就回退（`PITFALLS` **325** 的教训）。
4. **守卫 + 变异**：新检查项进 `selftest.py`，并配 `mutation_check.py` 注入
   （"转音细胞退化成固定音型 / 整曲一刀切"必须被抓）。
5. **不许自创依据**：转音密度必须有出处（B1 派生量要标注 / B2 直接量）；
   `check_song` 的模板依据白名单不许绕。
6. **曲目级回归**：拿 2–3 首**已认可**曲目重生成，报"变了几处 + 听感"（认可版即基准）。

## 7. 红线（每条都有代价）

1. **听感赢**：用户认可的版本就是基准；有"更好"的**证据**也先做 A/B 让他判。
2. **一次只改一个维度**：转音是一个维度，别顺手改音色/密度/段落。
3. **逐段，不许整曲一刀切**。
4. **别拿提取侧的检测结果当生成侧依据**：`ornament_probe` 在密集混音上参数敏感（52~155 处），
   只当线索；要当依据必须换成 §3-B2 的直接量。
5. **加工具/文档 = README + 自检 + 变异 + 预算 + `doc_map.py`**（`CONVENTION` §4）。

  那一类 —— 本工具只量"音高序列在不在"，**量不到"怎么奏"**。
