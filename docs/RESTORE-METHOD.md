## 0. 一句话结论（**先看这条，它决定要不要往下做**）

**还原的音质瓶颈在「音高内容」，不在音色 / 力度 / 织体 / 混音。**
实测：引擎自己生成的版本对原曲逐段音符级 F1 中位 **0.123**，而"直接从原曲分轨转录"
的版本是 **0.298**（该尺子对恒等输入的天花板 = **0.809**）。
每段最佳时间偏移都 ≈ 0（时间轴本来就对）→ **差异纯在音高内容**。
**所以在音高内容对齐之前，所有改音色/力度/混音的努力都不可能修好它。**

## 1. 工序（七步，照做）

| 步 | 做什么 | 关键数字 / 坑 |
|---|---|---|
| ① 分轨 | `demucs -n htdemucs`（4 轨）**与** `htdemucs_6s`（6 轨）**都跑** | 它们是**两个不同的分离模型**，同一首曲子的分轨**互为独立证据** |
| ② 转录 | 每条分轨各跑一遍 Basic Pitch；再跑 YourMT3+（**直接吃全混音**、视角独立） | 来源从 4 条扩到 **8 条**是 F1 提升的主因 |
| ③ 交叉验证合并 | 同 0.1s 格同音高合并 → **按来源精度软评分加权**（阈值 0.50） | **`other` 轨是假音主源**：被砍的 3528 音里 **2390 个只有它支撑** |
| ④ 物理修复 | 见 §3 的 9 项（每一项都要**硬证据**） | 音高越界 / 重叠 / 空洞格 / 力度突变 |
| ⑤ 编配 | 按**来源轨**分配声部（piano/guitar→Piano · bass→Bass · 长音→Strings），鼓沿用已对齐的那条 | 写成 `notes_extra`，**让引擎编配**，不要手工拼 MIDI |
| ⑥ 渲染 | `render_midi.py ... --width 1.4 --rms -16.0 --shelf 6.0 --hp 25 --low 2.0 --drive 1.2 --mid 4.0` | 默认参数不够，这套是实测收敛值 |
| ⑦ 后处理 | `band_match(±6dB)` → `set_width_exact(0.473)` → RMS −16.10 → ogg | **`render_midi` 不含这三步**，必须单独做 |

### 段落切分要细

实战用 **26 段 / 208 小节**（`S01`…`S26`，每段 8 小节），段名不带曲式含义。
**退化成"5 个大段"会丢掉段级控制力**（呼吸口、收尾、段间对比全靠段级参数）。

## 2. 转录能力：哪些**有效**、哪些**无效**（6 组实验，同一指标衡量）

| 实验 | 结果 |
|---|---|
| Basic Pitch 参数调敏感（onset .3/frame .2/minlen 60） | recall 0.44→0.74 但精度崩到 0.29 → **F1 反而降到 0.415** ❌ |
| 音频能量验证（f0 + 2/3/4 次谐波 ÷ 帧谱 RMS） | 只值 **+0.003** ❌（假音也多有真实泛音能量） |
| **碎片合并（同音高 ≤40ms）** | **大幅变差 0.481 → 0.283** ❌❌ 那些"碎片"是**真实重复起音** |
| 硬交叉验证 support ≥2 | 太严（只剩 1191 音）→ F1 0.232 ❌ |
| HPS 第二方法补漏 | 失败（显著度分不清泛音）❌ |
| **多分离模型集成 + 软评分** | **0.481 → 0.527** ✅ |

**权重可以无监督化**（改用"跨来源支持率"）—— 排序与监督版**完全一致**，
所以**没有模板的新曲子也能用**。

## 3. 九项物理修复（全部有硬证据，不是主观取舍）

| # | 缺陷 | 修复前 → 后 | 固化在哪 |
|---|---|---|---|
| 1 | 空洞格（某些时刻没有任何音在响） | 16 → **0** | — |
| 2 | 虚假重复音（逐帧找峰把持续音拆成多段） | 合并 **902 个** | — |
| 3 | 同轨同音高重叠（GM 音源吞音） | 340 → **15** | `patterns.legato_trim` |
| 4 | 鼓落点连击 | 逐小节对齐原曲鼓 stem 的检测值 | — |
| 5 | **丢 `set_tempo` → 渲染按 120BPM 算** | 419s → **336s**（多出 **87 秒静音**） | — |
| 6 | 音高越界（超 `TR_RANGE`） | 382 → **0** | `patterns.range_fix` |
| 7 | 弱起音（velocity<20，GM 里几乎无声） | 3 → **0** | 同上 |
| 8 | 同刻同音高重复（音源吞音） | 15/56 → **0** | 同上 |
| 9 | 段界力度突变（段末 vs 段首 >25） | 16 → **0** | `patterns.seg_fade` |

**必须配 18 项系统性体检**（`b35_health18.py` 模式）。其中"段间音符数突变"实测 11 处
**判定为不应修** —— 那是音乐的段落对比（原曲逐段 1.3~8.4 音/秒的呼吸），抹平反而失真。

## 4. 数据格式：`song.json` 要写成什么样

```jsonc
{
  "notes_extra": {
    "Piano": {
      "notes": [[小节, 拍内, 时值拍, 音高, 力度], ...],   // ⚠ 5 元组，力度必给
      "target": [每段目标音数, ...]                        // ⚠ 逐段数组，按段对齐密度
    }
  },
  "sections": [
    {"name": "S01", "bars": 8, "melody": "M",
     "melody_extra": [[小节, 拍, 时值, 音高, 力度], ...],  // 段级补充旋律
     "arr": {"melody_prog": …, "mix": …, "perc_vel_max": …, "density": …}}
  ],
  "_octfix": …,        // 八度修正留痕
  "programs": {…}      // 显式音色
}
```

**三条最容易被漏掉的**（实战对照得出的差距）：

1. **力度必须逐音给**（第 5 个元素）。缺了它 → 引擎用默认力度 → **"打字机"听感**。
   实测对照：带力度的版本 **17773/17773 全带**，不带的 **0/23033**。
2. **`target` 逐段给**。扒谱天然**过采样**（实测 43.6 音/小节 vs 原曲 27.3 = **1.60×**），
   而 `arr.density` 的固定上限**压不住它**，段间起伏反而被放大（σ 9.3 vs 4.4）。
   **给了 target 就按该段总音数等间隔抽样、从小到大均匀铺开**（不是每小节砍一刀 ——
   那会在小节边界留规律缺口）。
3. **`melody_extra`**（段级补充旋律）与 **`_octfix`**（八度修正留痕）都要有。

⚠ `notes_extra` **两种写法引擎都吃**：`{'notes': [...], 'target': [...]}` 与直接给 list。
**给 target 才能精确对齐密度；只给 list 只能用 `density` 粗档。**

## 5. 渲染后处理（`render_midi` 之外的三步）

```bash
# 渲染
python scripts/render_midi.py <mid> <out> --width 1.4 --rms -16.0 \
       --shelf 6.0 --hp 25 --low 2.0 --drive 1.2 --mid 4.0
# 后处理（三步，缺一不可）
python scripts/band_match.py <out>.wav <参考曲> <out>_bm.wav   # 逐带对齐（±6dB 上限）
#   → set_width_exact(0.473)   # 宽度对齐到参考
#   → RMS −16.10               # 响度对齐
```
目标值（BGM35）：**宽度 0.473 · RMS −16.10 · 平均带差 0.86dB**。
⚠ `band_match` 的 `--max-gain` 默认 ±6dB；**需要超过 6dB 说明编配缺层**，
该回去改编配，不是把 EQ 拉爆（踩过：整体 +9dB 补高频，`octave` 反而 78→41）。

## 6. 度量纪律（**这一节比上面所有技术都重要**）

1. **尺子先自检**：拿**恒等输入**跑一遍。实测该尺子对恒等输入只有 0.753–0.943
   （16 分格边界抖动）—— **天花板不是 1.0**，报数必须说明天花板。
2. **只信"用户认可的版本"**：新指标先拿它自检 ——
   **它在认可版本上给出「差」的读数时，那是指标错，不是版本错。**
3. **七个自造并推翻的坏读数**（别重造）：CQT 谱峰当"每起音音数"（高估 10 倍）·
   "音符数/秒"当"起音率" · 逐帧 onset 包络相关（差 10ms 即归零）· CQT 音高重心 ·
   模板时间轴线性移植 · `section_gap` 当不连续主因 · CENS 帧率换算。
4. **指标略升 ≠ 听感更好**：接上 YourMT3 后 F1 0.527→0.532、recall 0.516→0.575，
   但音符数 +21%、原始渲染出现削波 —— **必须 A/B 听**。
5. **局部修改必须能证明"没碰的地方一字不变"**（例：只重触发两个时间窗的长音，
   F1 在该窗口内升、其它段数值完全不动）。

## 9. 还没解决的

**「点状 / 一部分节奏太快」在物理层查不出对应缺陷**：起音率 7.4/秒（与用户认可的版本同）·
每起音 3.0 音（同）· 时值中位 0.30 拍（同）· 空洞格 0 · 同刻重复 0 · 段界突变 0（**均优于**）。
最可能的剩余原因是**音色包络**（木琴 / Lead 8 / 鼓采样都是点状衰减），
但用户明确说过"**不关音源的事**"，所以**只能靠听感判据推进**。
