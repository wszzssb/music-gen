补上 MIDI 的"力度"维度 —— 用户："不只是音源的问题，MIDI 就不像了"

## 用户指出的这个判断可以直接验证，结论是：对

扒谱只输出 `[小节, 拍内, 时值, 音高]`（音高 + 时值两维），而
`song_engine.build_events` 把 `notes_extra` 写进事件时用的是**固定 84**。
实测重制 MIDI：

| 轨 | 音数 | 力度取值 | 分布 |
|---|---|---|---|
| Piano / Hook / Arp / Bass | 3038 | **1 种（全 84）** | 平 |
| Melody | 442 | 2 种 + 乐句包络 | 近假 |

而原曲对应分轨的真实强弱跨度（10ms 包络的分位差）：
**piano 38.0dB · guitar 44.5dB · bass 53.8dB · other 16.6dB**。

听感就是"每个音一样重、像打字机"。**换音源救不了** —— 同一份 MIDI 换任何音源，
力度曲线还是平的。所以用户说"不只是音源的问题"，是对的。

## 修法（`b35_vel.py`）

回到 Demucs 分轨音频，对**每个音符**量起音处的真实电平：
起点 +20ms 起 80ms 窗的**峰值包络**（避开瞬态本身与音尾衰减），
再按**逐轨 5%~95% 分位**把 dB 拉伸映射到 velocity（保留轨内相对动态，
不让个别弱音把整轨压扁）。

结果：Bass 34 种取值、Piano 90 种、Hook 90 种、Arp 94 种、Melody 51 种。

引擎侧（通用能力，向后兼容）：
· `notes_extra` 的音符可带**第 5 个元素 = 力度**
· `melody` / `melody_extra` 的音符同样可带第 5 个元素（原来硬编码 96）
· `check_song` 的范围校验放行 5 元音符

## ⚠ 为什么分数几乎没动（这条比修复本身更重要）

| | 力度修复前 | 力度修复后 |
|---|---|---|
| 总分 | 74.9 | **75.0** |
| density | 70.5 | 78.5 |
| grid | 66.7 | 62.5 |
| octave / variation / timbre | 34.3 / 81.1 / 76.9 | 33.0 / 81.2 / 76.8 |

**改动前后总分差 0.1** —— 因为 `similarity.py` 的六个轴全是**时间平均的统计量**
（和弦序列、节奏格、逐段密度、倍频程能量、质心/宽度、逐块方差），
**没有一个轴看"单个音有多强"**：力度只改音符的相对强弱，
既不改变平均频谱、也不改变密度计数。

**这就是"为什么最开始发现不了"的答案**：
工具能测的都是"每段有多少音、频谱什么形状"，而"像不像"里很大一块
（力度、演奏法、音色细节）**它测不到**。所以：

- `similarity.py` 的分数**只用于对齐"结构层"**（和弦/密度/段间走势），
  它到 75 分不代表"像"，只代表"结构对齐了"；
- **"像不像"必须由人试听确认**（用户听得到力度和演奏法，工具听不到）。
