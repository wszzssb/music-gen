## 4. 机制（**代码层读出来的，注意：没有消融证据**）

- 落点在动机模式下主要来自 **`CELLS_BY_N` / `_make_cell` 这套固定候选表**（每小节 3~6 个落点的组合）；
  画像只从两条窄缝进来：① **`_decorate_cell`**（**每小节至多搬一个**装饰音到画像加权的弱格）
  ② 候选**打分**里的 `onset_tvd`（只影响"挑哪条候选"，不当门槛）。
- **`_cap_onsets`** 补音时只补**反拍八分格 2/6**；它认的"强拍"只有**格 0 与格 8**
  ⇒ 裁剪/补充都在把重心往拍内中后段推。
- **守卫只卡上界**：`t_melody_form_rules` 查的是 `g0 ≤ 22%`、`last8 ≥ 65%`、密度区间 —— **没有下界**。
  历史上这条是为治**旧版 g0 过高（25.7%）**而设的，现在**反向过冲**到 3.7%，一路不会被拦；
  而 `SKILL.md` 里记的真实值是**格 0 占比 12.9%**。

### 4b. ✅ 消融结果（2026-10-06 续，实测 —— 上面的读代码猜测**被否掉两条**）

16 首 × 7 变体 × seed {1,2,3,7} = 64 条/档，**同曲同 seed 逐条配对**（`g0` 与
`placement_survey` 同源）：

| 变体 | 做了什么 | g0 均值 | 相对 base2 配对差（中位 / 同向） |
|---|---|---|---|
| `base2` | 现引擎复刻 | 8.2% | — |
| **`strong0`** | 候选表只留"首落点 = 格 0" | **28.1%** | **+21.0pt · 62/64** |
| **`ncap0`** | 候选表只留"首落点 ≠ 格 0" | **0.4%** | **−7.3pt · 0/64** |
| `nocap` | `_cap_onsets` 恒等 | 8.0% | −0.3pt · 25/64 |
| `nodecor` | `_decorate_cell` 恒等 | 8.4% | +0.0pt · 31/64 |
| `alloff` | 上两个同时关 | 8.2% | +0.3pt · 34/64 |
| `nocell` | 整个节奏细胞层关掉 | 9.5% | +0.2pt · 32/64 |

- **逐级 checkpoint**（16 首 × 4 seed）：动机层出口 g0 均值 **13.0%**（范围 2.5~32.1%）→
  细胞层之后 **8.2%**（范围 3.7~17.1%）⇒ 细胞层**把入口的分布按表的供给归一化**，
  动机层其实比最终好。
- **部件实动计数**（64 曲趟）：`_decorate_cell` 真搬走 1130 次，**其中搬掉的是格 0 只有 91 次（8%）**；
  `_cap_onsets` 补 1136 个落点（平均 17.8/曲趟）、裁 91 个；`_ensure_strong_onsets`
  救回格 0 229 个、**挪走 0 个**；`_pick_variant` 抽中"含格 0"的细胞 **20.5%**。
- **候选池并不缺格 0**：按 `_cell_candidates` 的同一约束枚举，1136 个合法候选里
  **37.1% 含格 0**（n=4：380 个池、101 个含格 0）⇒ 是**挑选**（`_cell_fit` 只奖励
  "与画像分布重叠 + 末落点靠后"，没有正拍覆盖这一项）把供给压到 7%，不是约束卡死。
- ⚠ **`_cap_onsets` 补音的落点是写死的第 3/4 拍**（4/4 的格 4 与 6；3/4 只有一格）
  ⇒ 每补一个音就多一个"非格 0"落点，**同时稀释 g0 与让位置僵化**。
- ⚠ 方法学：`_decorate_cell` 每次调用都抽随机数 ⇒ 关掉它会挪动随机序列；单 seed 读数会飘
  （103 seed 1 曾读成 "nodecor +5.7pt"，64 条配对后回到 +0.0pt）——**判据取多 seed 配对中位**。

⚠ **上面三条是"读代码 + 读注释"得到的**，本轮只量了**结果**（16 首 g0 都低），
**没量过每一处各贡献多少** —— 这正是下一步要补的。
