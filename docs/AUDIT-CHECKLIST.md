# 开工前必查清单（全维度）

> 用户 2026-09-16 的要求：**"能不能让最开始就发现所有要注意的元素"**。
>
> 之前是**踩一个补一个**：先"乱"（密度/鼓/泛音）→ 再"旋律轨静音"（小节号口径）
> → 再"MIDI 不像"（力度全 84）…… 每一条都是**用户先听出来**才发现，
> 而每次只盯着手上那一个轴，**其余维度处在"没人查"的状态**。
>
> 这份清单把"该看哪些维度"固定下来。**能自动测的用 `scripts/audit.py` 一次跑完**；
> **测不到的必须显式列出并交给人耳** —— 否则会误以为"报告全绿 = 听着像"，
> 而这是踩过的：`similarity.py` 六个轴全是时间平均统计量，
> 补完力度（3038 个音从"全 84"变成真实动态）**总分只动 0.1**。

跑法：

```
python scripts\audit.py <参考音频/目录> <我的音频> --bpm N \
    --mine-json <song.json> --ref-chords <扒好的和弦.txt> --midi <我的.mid>
```

---

## 第 0 层：先问"我到底在比什么"

| # | 项 | 判据 / 口径 | 工具 |
|---|---|---|---|
| 0.1 | 参考曲的 BPM 是否**钉死** | 音频测速对连奏编配会误判（106→154.3）；一律取 MIDI tempo 或人工确认 | `--bpm` |
| 0.2 | 参考曲的**拍号** | 分析侧按 4/4 切小节，非 4/4 的参考曲做结构对比会全错 | `profile_ref --meter` |
| 0.3 | 参考曲的**调式** | 判错=全盘返工 | `melody_profile.py` 音级直方图 |
| 0.4 | 比的是**音频**还是**MIDI** | 音频层能查频谱/宽度/动态；MIDI 层才能查力度/时值/演奏法 —— **两层都要查** | 本文件第 2/3 层 |

## 第 1 层：结构层（工具能测，参考线已定）

| # | 项 | 参考线 | 不达标说明什么 |
|---|---|---|---|
| 1.1 | `chord` 和弦序列一致率 | ≥90 | 和弦没照抄（**读 `song.json`，别重扒**：重扒对 `m7↔7`、`sus4↔7` 只有 ~39% 分辨力） |
| 1.2 | `grid` 节奏格命中率 | ≥60 | 鼓型不对（逐小节 vs 全曲平均，见 `MAKE-IT-SOUND-ALIKE.md`） |
| 1.3 | `density` 逐段密度相关 | ≥65 | 疏密走势没跟着参考曲（要按段对齐） |
| 1.4 | `octave` 倍频程平衡 | ≥45 | 整条频谱倾斜（成片差 → `band_match.py`；孤立一两带差 → 编配问题） |
| 1.5 | `timbre` 质心/宽度/RMS | ≥65 | 音色或混音平衡不对 |
| 1.6 | `variation` 段间变化度 | ≥55 | 段间起伏比参考曲剧烈或太平（鼓用固定网格 → 26.7；逐段鼓 → 79.9） |
| 1.7 | 总分 | 记录**基线**再改 | 不看绝对值，看"这一改有没有让它涨"；**分数≠像**（见文件头） |

## 第 2 层：频谱与动态层

| # | 项 | 参考线 | 工具 |
|---|---|---|---|
| 2.1 | 质心 | 差 ≤25% | `metrics.profile` |
| 2.2 | **立体声宽度** | 差 ≤25%（**易漏**：原曲 0.473 vs 我 0.303 = 差 36%，听感"太窄、都挤在中间"） | `metrics.width` / `set_width_exact` |
| 2.3 | L/R 相关系数 | 原曲 0.636 vs 我 0.836（同一件事的另一面） | 自算 |
| 2.4 | RMS 电平 | 差 ≤3dB | `metrics.profile` |
| 2.5 | 倍频程平均带差 | ≤3dB（满分线） | `band_match.py --report` |
| 2.6 | 最差单带 | ≤3dB；**成片**才用 EQ，孤立一两带是编配问题 | 同上 |
| 2.7 | 段间能量起伏 | 与参考曲的 `structure_db` 比（`energy_curve_db` → 每段 `arr.mix`） | `theme_pack` / `new_song` |
| 2.8 | 每 8 小节块的电平跨度 | 原曲 BGM35 中位 3.6dB、最静块 −19.0dB | `b35_variation.py` |
| 2.9 | 是否有**极静段** | BGM35 最静 −34.2dB（我们常常最静才 −18dB） | 同上 |
| 2.10 | 收尾是否逐小节渐弱 | BGM35 收尾 5 小节衰减到 −38dB | 同上 |

## 第 3 层：演奏层（**最容易被整套忽略的一层**）

| # | 项 | 参考线 | 说明 |
|---|---|---|---|
| 3.1 | **MIDI 力度取值种数** | ≥8 种/轨；**1 种 = 打字机** | 实测踩过：Piano/Hook/Arp/Bass **3038 个音全是 84**，而原曲这几条分轨真实跨度 **38/44.5/53.8dB**。换音源救不了 |
| 3.2 | 逐轨力度种数 | 每轨 ≥5 种 | 生成轨（Pad/Strings/Glock）常常只有 1~3 种 —— 长音层可用，但要知道它是"平的" |
| 3.3 | **音符时值分布** | 中位与画像比；碎音（<0.12 拍）≤15% | 转录把长音切碎 = 听感"发抖" |
| 3.4 | **起音时刻精度** | 我量化到 **0.25 拍**；参考曲可能有摇摆/提前量 | ⚠ 工具测不到，见第 5 层 |
| 3.5 | 和弦音是否**连奏** | 一个和弦该是一个长音还是几个短音 | ⚠ 工具测不到 |
| 3.6 | 延音踏板（CC64） | 真实钢琴的延音全靠它 | ⚠ 我完全没写 |
| 3.7 | 力度曲线（渐强/渐弱） | 逐音力度有了，但**句内走势**要靠它 | 逐音力度可表达 |
| 3.8 | 演奏法/音色切换（program change） | 段间换音色 | `sections[i].arr.melody_prog` |

## 第 4 层：编配层

| # | 项 | 参考线 | 说明 |
|---|---|---|---|
| 4.1 | **同时发声的乐器数** | 中位 ≤4、P75 ≤4.5（原曲 3.6/3.9） | >5 就是"堆叠"，用户口径"乱" |
| 4.2 | 同时发声音符数（复音度） | 中位与原曲比（原曲 6.8） | 过高 = 糊 |
| 4.3 | 每小节音符数 / 原曲 | 1.0× 最好；1.44× 偏满 | `b35_seccmp.py` 口径 |
| 4.4 | 逐段每小节音符数**相关系数** | ≥0.8 | "该疏则疏"是否跟着参考曲 |
| 4.5 | 鼓的**逐段活跃度** | 跟着参考曲（原曲 2.2~26.5 格/小节波动） | 固定网格 = 不呼吸 |
| 4.6 | 段间乐器组合 Jaccard | 别太高（0.86 = "每段都一样"） | `t_arr_role_variety` |
| 4.7 | 轨间平衡 | 伴奏不盖过旋律 | `t_track_balance` |
| 4.8 | 主奏起音滞后 | ≤20ms | `t_lead_timbre_attack` |

## 第 5 层：**工具测不到的（必须人耳，逐条问自己）**

1. **起音时刻有没有摇摆/提前量** —— 我只量化到 0.25 拍，参考曲的"人味"可能就在这几十毫秒里。
2. **和弦音该连的有没有连** —— 转录可能把一个和弦拆成几个音，听感"碎"。
3. **钢琴延音踏板** —— 真实钢琴的延音全靠它，我的 MIDI 里没有。
4. **演奏法/滑音/颤音** —— GM 音源也表达不了。
5. **音色本身** —— GM（GeneralUser GS）vs 商业采样库，这是已知天花板（`MIDI.md`）。
6. **旋律好不好听** —— 形态能测（密度/落点/重复率），"好听"测不了。
7. **段间过渡顺不顺** —— 能测"渐弱/渐入 ≥4dB"（`t_section_transition`），但"顺不顺"是听感。
8. **整体像不像** —— 只能由用户确认。

## 一句话用法

**开工前**跑一遍 `audit.py` 拿到"偏差项清单" → **动手前一次列全**要改的项
（用户的工作纪律之一）→ 改完再跑一次对比。
**测不到的 8 条**在交付时逐条说清"没验证什么"，不许用"分数 75"冒充"像"。

## 附：这份清单第一次跑出来的成绩（BGM35 还原曲，2026-09-16）

第一次跑 `audit.py` 就抓到 **6 项偏差，其中 2 项是之前从没查过的维度**：

| 偏差项 | 修法 | 结果 |
|---|---|---|
| 立体声宽度差 **36%**（0.303 vs 0.473） | 渲染链最后用 `set_width_exact` 钉死目标值 | `timbre` 76.8 → **88.6** |
| Pad/Strings 力度各只有 **1 种** | 新增 `patterns.dyn_vel`（正弦 + 确定性哈希抖动） | Pad 1→20 种、Strings 1→16 种 |
| 质心差 32% / octave 33 / 最差带 4.8dB | `band_match.py`（三者同源：高频成片偏多） | octave 33 → **57**、质心差 → **12%** |
| MIDI 力度全平（3038 个音一个值） | 按分轨音频逐音峰值包络补 velocity | 每轨 29~113 种取值 |

最终：**结构层 6 项 + 频谱层 5 项 + 演奏层 12 项全部达标**，总分 76.0 → **78.8**；
剩下只有"人耳"那 8 条。

> ⚠ 注意顺序：**先修"工具能测的"再交人耳听**。反过来做的话，
> 用户每次都会先听出"太窄""力度太平"这类**本来能自动查出来**的问题，
> 而这些问题会在好几轮对话里反复消耗注意力（这就是这份清单存在的理由）。
