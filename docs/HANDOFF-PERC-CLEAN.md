### 2.4 模型侧的硬边界（实测，非文档抄来）

`f_min 50 / f_max 8000`（写死）· `hop_length 300 @16kHz` = **帧移 18.75ms** · `shift_step_ms 10` ·
**解码上限 256 步** · 解码器 `t5-v1_1-small` · 官方训练 `total_steps 100000` / `BSZ 24` /
`adamwscale`+`cosine` / pitch ±2 / amp 0.8–1.1 / 分轨交叉增强 `no_instr_overlap=True` ·

⚠ **`transcribe_ymt3.py` 的参数里没有任何 onset/frame 阈值** —— token 自回归解码，每个 token 直接成音，

## 4. 我（上一个对话）犯的错 —— 别重犯

1. **套套逻辑**：用分轨能量**剔**、再用分轨能量**量** ⇒ 精度必然上升。证据：C 版"精度 31.6%→47.5%、准入 1/8→3/8"，而**绝对命中数 3389→3388（一个没多）**，只是分母小了。
2. **硬编码 BPM**：写死 `SPB=60/71`，而"去鼓版"是 **141.6 BPM** 记谱（158 小节 vs 基线 79）⇒ 时间轴错一倍、得出"独立基音仅 6.1%"的**假读数**（真值 19.9%）。**必须逐曲目读它自己的 `bpm`**。
3. **改曲名被覆盖**：`cp -r` 后改 `song.json` 的 `name`，随后的清理脚本**从源目录读数据写盘**、把 name 覆盖回去 ⇒ `render.json.mid` 与实际产出名不符 ⇒ `make_song` 报"找不到 MIDI"（连卡两轮）。
4. **污染曲库**：建 10 个实验曲目 ⇒ 全库自检 **232/236**（4 项红）；移出 9 个 + 补 `notes.md` 与**带实测数字的豁免留痕**后回到 **236/236**。（⚠ 本轮做端到端验证时又建了 5 个 `perc_partial_probe*`，**已全部删除** —— 验完即清。）
5. **顺序错**：`extract_finish.py` 必须在**渲染之后**跑（它内部会重跑 `make_song`）—— 放前面会"MIDI 还不存在 ⇒ 两级都失败"。
