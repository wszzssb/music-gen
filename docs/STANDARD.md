# 音乐家使用标准（最高标准）

> **这份是什么**：如果一位音乐家用本软件做音乐，**要满足的全部要求**都在这里。
> 红线（§1）优先级最高 —— 与任何指标冲突时**以红线为准**。
> **下一个对话接手时**：先读这份，再看 `SKILL.md` 路由表（§7 给了顺序）。
> **写法纪律**：只写实测过的（带读数/出处）；不许写"应该没问题"；每条都要有**怎么验**。

---

## 1. 五条红线（不可协商）

| # | 红线 | 出处 / 依据 | 怎么验 |
|---|---|---|---|
| 1 | **听感 > 一切指标**。指标只是"找问题的尺子"，不是判决；两者冲突时以耳朵为准 | 用户口径："听感赢"；`CASE-BGM36.md` 记着一次指标与听感背离 | 交付时必须写清"**听感还没判**"，不能拿读数冒充 |
| 2 | **和谐优先**。"搭不搭"是可查的硬判据，不协和优先修 | `SKILL.md` 四条铁律第一条；守卫 `melody_chord_fit` | 强拍和弦音占比 ≥70%、♭9 ≤2 处 |
| 3 | **依据可查**。曲子长什么样，必须能追到"哪几首真实模板"；不许拍脑袋 | `docs/THEME-PACK.md`；守卫 `theme_basis_whitelist` | `song.json` 的 `theme.templates` 与主题包一致 |
| 4 | **改前核基准**。逐轨音符数 + SHA256，能按指纹恢复；**改必须分段**（逐轨×逐小节表） | `SKILL.md` 铁律 2/3 | 改前打印基准、改后复核；分段表存进 `notes.md` |

## 2. 动笔前的四件事（顺序不能换）

1. **开面板**：`http://127.0.0.1:8765/`（铁律 4）。改完前端资源**要升版本号**（`?v=N`），
   否则浏览器/WebView2 用缓存的旧文件 —— 实测"改了却看不到"有一半是这个。
2. **核基准 + 备份**：`song.json` 的 SHA256、逐轨音符数；备份到 `D:\test\_tmp\<任务>\backup\`。
   ⚠ `songs/` 是指向 `songs_direct/` 的 **junction**，而 `songs_direct` 在 `.gitignore` 里 ——
   **删除要用 `mv` 移走，不能用 `rm`**（`PITFALLS 351`）。
3. **先量再改**：写 20 行离线脚本量清楚，**别拿全量渲染当试验台**（`PITFALLS 17.5`）。
4. **想清口径**：你要改的东西、守卫量到的东西、门服务的对象，**是不是同一个**。
   本会话在这上面连踩四种错法（`PITFALLS 353/359/360/362`）：
   **口径分叉 · 材料不同类 · 维度不全 · 门不同源**。
   ⇒ 加/改闭环一维时，**逐项对照守卫的判据表达式**（门值 · 容差 · 样本量下限）。

## 3. 交付时必须附的证据（缺一样就不算交付）

- **读数**：改前/改后，**同口径**（同一函数量的）
- **分段改动表**：逐轨×逐小节；若只改了一个字段，**明说"只改了这一个字段"**
- **绝对路径**：能直接粘进资源管理器（`D:\...\xxx_sf.ogg`），不要只说文件名
- **备份与回退**：备份在哪、怎么退回去
- **诚实清单**：**没验证什么** · 已知偏差 · 哪条读数可能不可靠（及为什么）
- ⚠ 反面教材：本会话有一次提交信息里写了"端到端验证通过"，而当时**面板根本没在跑**、
  验证是空转的（`PITFALLS 363`）⇒ **任何 HTTP 验证第一步先断言服务活着（200）**。

## 5. 能力边界（**别向用户许诺做不到的**）

| 想做的事 | 现状 | 依据 |
|---|---|---|
| **拍号** | 是**主题的属性**（waltz 3/4，其余 4/4），不是曲子的自由参数 | `new_song.py:1197`；`melody_gen` **只支持 4/4 与 3/4**（其它拍号"旋律需手写"） |
| **结构（总小节）** | 由主题模板算：`段数 = 模板小节中位 ÷ 段长`（夹 3~14）· 段长固定 8 | `theme_pack.py:1053`。实测 15 主题：**7~16 段 · 48~120 小节 · 96~269 秒** |
| **改结构** | 允许，但**必须留痕**（段数 ≠ 主题包 `form.plan` 时要有 `imitate:`） | 守卫 `imitate_path_marked`（`selftest.py:9482`） |
| **时长 ↔ BPM** | 同一件事的两种写法：`秒 = 小节数 × 每小节四分 × 60 ÷ BPM`；创作台已有「想要的时长（秒）」框 | `studio/web/create.js` 的 `barBeats/estSeconds/suggestBpm` |
| **编配用哪几件** | `--arr-only "piano,strings"`（白名单）；**空 = `none` = 只留主奏**；面板：创作台「生成时只用这几件」 | `new_song._apply_arr_only` |
| **主奏用什么乐器** | `--lead "40"`（GM 号）或 `--lead sax,trumpet`（多件按段轮换）；面板是**两级选择**（16 大类 → 该类的 8 个音色） | `new_song.build_from_theme` 的 lead 分支；`studio/web/gm.js` |
| **独奏化（改已有曲子）** | 独立页 `/solo`：选一首 + 选**一件**乐器（独奏=一件）；命令行 `--instrument`（单件，合并声部）/ `--instruments a,b`（多件，保留声部） | `scripts/solo_instrument.py` |
| **听感** | **只能人耳判**；`AUDIO-CRITIC`（Qwen2-Audio / Music Flamingo）是辅助线索，不是判据 | 红线 1 |

## 6. 已知未决（接手别重复踩）

1. **`density_dynamic_range` 2 条红**（`102_classic_marble` 6.2 倍 / `114_waltz_court` 7.0 倍，门 8）：
   是"编配按 `arr_share` 变薄"的副作用。试过三招（主歌 density 2→1、裁主线贝斯、引子去鼓）都卡在
   "最静小节仍 ≥5 音"（骨架层 `bass`+`piano` 永在 + 主题 `density_curve` 覆盖 `arr.density`）。
   **门不能凭手头材料改**：门依据是 13 首商业 BGM 画像，我量的是 218 首 MIDI 模板
   （P10 4.0 / 中位 8.0 / P90 16.0）—— 材料不同类（`PITFALLS 359`）。
2. **中高频归因已定，但结论反直觉**：`ask_20261008_2216` 的 2500–5000Hz 比参考高 **+12.9dB**，
   逐轨**消除法**显示 **Melody（长笛）贡献 14.2dB，其余 8 轨合计 ≈0.1dB** ⇒ 换 Hook 音色、
   降 Perc、换 Arp 全是无效改法（都试过）。**真正要动的是主奏音色**（换电钢后该档 −14.0dB 到 −1.1）。
   ⇒ 教训：**别用 `probe_timbre --solo` 的 raw dB 当"总混贡献"**，要逐轨静音重渲染（消除法）。
3. **守卫欠账**：`--arr-only` / `--lead` / 多乐器 `--instruments` 这三处新参数**还没配自检与变异用例**。
4. 主题级的下一个改动候选：`tender` 等"柔"主题的主奏池（长笛/短笛/方波/合成铜管）偏亮 ⇒
   要么按频段筛池，要么把"柔主题"的主奏候选换成更暗的音色。
