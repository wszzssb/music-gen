# STUDIO-WORKFLOW —— 音乐任务里**必须**调动 studio 的时机

> 用户 2026-09-16 要求："写一下要调动工具 `D:\test\galgame\music-gen\studio`"，
> 并明确 **范围 = 所有与音乐相关的活**（写歌、改歌、扒谱、分析、体检、对比、混音）。
>
> 背景：**我（agent）在 BGM35 还原任务里一次都没用过它** —— 全程盲写 MIDI、
> 用 6 分钟的全曲渲染做迭代、从不和参考曲同位置 A/B。
> 而 studio 的实测速度是：**试听本段 1~3 秒 · 切片渲染 0.36 秒 · 整曲渲染 18~40 秒**。
> 这一条差距 = 一次迭代 6 分钟 vs 3 秒 = **120 倍**。

---

## 0. 一句话规则

**"看一眼 / 听一下 / 试一版 / 核一遍"这类动作一律走 studio；
"批量、可复现、要留痕"的动作走 CLI —— 但动手前先想想面板是不是更快。**
原因不是 studio 更强，而是**它的反馈回路短两个数量级**。
（面板驱动的是同一批 `scripts\*`，改的永远是 `song.json`，两条路结果一致。）

| 动作 | CLI（我原来一直这么做） | studio | 倍数 |
|---|---|---|---|
| 听一段改动 | 全曲渲染 **6 分钟**（`b35_render.py`） | 「⚡ 试听本段」**1~3 秒** | **~150×** |
| 试一版编配 | 改 song.json → 渲染 → 量指标，一轮 6~8 分钟 | 「🧬 候选搜索」一轮 **11 秒**（48 次渲染预算） | **~40×** |
| 整曲渲染 | 6 分钟（含我自己的后处理链） | **18~40 秒** | **~10×** |

## 1. 五个"必须开 studio"的时刻

> 范围是**所有音乐相关的活** —— 下面五条里，⑤ 属于混音、④ 属于"找问题"，
> 扒谱/分析/体检同样该进来核（扒谱结果在面板里对着卷帘看，比只看 JSON 快得多）。

### ① 拿到一个 `.mid` / 要对比两版 MIDI —— 立刻 `/editor` 导入

**这次就栽在这里**：用户放了 `D:\test\galgame\BGM35 (1).mid` 说"比你的像多了"，
我却只用脚本统计它的轨数/力度，**从没在钢琴卷帘上看它长什么样**。
一眼能看出来的东西（单轨 vs 9 轨、有没有鼓、音符密度分布）我花了十几分钟用脚本推。

```
studio\start.cmd            # 已在跑则只开浏览器
http://127.0.0.1:8765/editor
```

### ⚠ `--root` vs `--lib`（2026-09-16 拆开，踩过）

| 参数 | 含义 | 何时改 |
|---|---|---|
| `--root` | **工具链根**（含 `scripts/`、`studio/`、`refs/`） | 基本不用改 |
| `--lib` | **曲库根**（含 `songs/`；`export/` 跟着它走） | 想把曲库放别处时用它 |

**为什么拆**：原来一个 `ROOT` 同时当"工具链根"和"曲库根"
（`ROOT/scripts` 找工具、`ROOT/songs` 找曲目）。把 `--root` 指到**外置曲库**后，
连 `scripts/render_midi.py` 都找不到 —— 用户实测报错：

```
!! 渲染失败：RuntimeError: 渲染失败（rc=2）
can't open file 'D:\test\llm_direct\b35_studio\scripts\render_midi.py'
```

现在"工具链在原地、曲库外置"互不干扰（`--root` 指错会**立刻报错退出**，不再拖到渲染才炸）：

```powershell
# 曲库外置（实验曲不进仓库曲库，避免污染 selftest 的验收信号）
python studio\server.py --port 8765 --lib D:\test\llm_direct\b35_studio
```

**另外两个坑**：
- `edit_import_path` **只允许导入工具链目录内的文件**（安全设计）。导外部 `.mid`
  要用**字节上传** `{name, data_b64}`（浏览器里就是"选文件"）。
- 编辑器渲染 API 的参数位置不同：`POST /api/ed/render-audio?eid=<eid>`
  （`eid` 在 **query**，body 放 `model`/`force`），轮询 `GET /api/ed/render-status?t=<task>`
  （用响应里的 **task**）。放错会得到 `非法会话 id` / 404。
- 导入任意 `.mid`（Type 0/1）→ 全轨卷帘 → **同屏对比两版**
- 默认**只读**（🔒），点右上角切 `✏️ 编辑中` 才能改
- 「🎵 按小节识别和弦」（带置信度）—— 比 `analyze_chords.py` 多一个"看得见的置信度"
- 「🎧 渲染音频」= 与引擎面板**同一条 `render_midi.py` 管线**（GeneralUser GS）

**扒谱/转录的结果也在这里核**：转录完（`bass_notes` / `piano_notes` / CQT 脚本）
先把 `.mid` 导进 `/editor` **对着卷帘看一眼** ——
漏音、音区飘（本轮踩过：钢琴整体偏高 4.77 半音、开头 0.4 秒整个丢了）、
同音高重复堆叠，**在卷帘上是几秒钟能看出来的事**，而用脚本统计要跑好几轮。

### ② 改了任何编配/和弦/力度 —— 先「⚡ 试听本段」，别整曲渲染

定位：`/` 页 → 选中段落 → 「⚡ 试听本段」（只渲染当前段落切片并循环，1~3 秒）。
**改一版立刻听**。只有"确认这一版对了"才升级到整曲渲染。

### ③ 怀疑"像不像" —— 用「参考曲 A/B」同位置切换

传输条可切「主混音 / 分轨混音 / **参考曲**」，**同位置、同循环区间**。
我之前的做法是"渲染全曲 → 跑 `similarity.py` → 看六个轴的数"，
但那个工具**测不到力度/声部厚度**（实测：补完力度总分只动 0.1）。
**同位置来回切，耳朵 1 秒就能判断**，比六个轴准。

### ④ 判断"哪一段不像" —— 指标按**时间窗**看

指标面板支持按时间窗切：**引子 / 安静段 / 主体段 / 尾奏**
（绝对倍频程差 + 占用率墙/点 + RMS/宽度/质心，同 `bands_abs.py` 口径）。
我一直用全曲平均，结果"开头不像"这个信息被平均掉了 —— 用户提了三次我才去逐小节量。

### ⑤ 混音层的问题 —— 「⬇ 载入分轨」+ 实时混音台

分轨同时播放，推子/声像/静音/**独奏**/电平表，「↩ 写回」、「🔊 以当前混音渲染」。
- **独奏某轨**是定位"哪件乐器在捣乱"的最快手段（比 `probe_timbre.py --solo` 直观）
- 「🎚 自动配平」解方程求每轨 CC7（±6dB 护栏）→ 真渲染 → 成绩单 → **更好才留、更差自动回滚**

## 2. 按任务阶段的工作流（推荐顺序）

| 阶段 | 用什么 | 为什么 |
|---|---|---|
| ① 拿到参考曲 | `profile_ref.py` / `theme_pack.py`（CLI，留痕） | 要写进画像，要可复现 |
| ② 扒带/转录 | CLI（`bass_notes` / `demucs` / CQT 脚本） | 批量、可复现 |
| ③ **对着参考曲调编配** | **studio `/`：A/B + 试听本段 + 候选搜索** | 反馈 1~3 秒，耳朵直接判断 |
| ④ 手改旋律 | **studio `/` 卷帘**（Melody 可增删拖、Alt+拖改力度、和弦内音导引带） | 看得见才改得准 |
| ⑤ 编辑外部 MIDI | **studio `/editor`** | 卷帘 + 量化 + 力度渐变 + 往返校验 |
| ⑥ 定稿渲染 | CLI `make_song.py`（或 studio「✨ 渲染+调参」） | 要留痕、要跑全套体检 |
| ⑦ 交付前体检 | CLI `audit.py` + `check_song.py` + selftest | 可复现的门 |

## 3. 边界（别用错）

- **只有 Melody 轨能手写音符**，其它轨由引擎按和弦 + 编排生成 ——
  改"和弦/开关/CC7"才是正确改法，别去卷帘里硬改（会被下次作曲覆盖）。
- 混音台推子是线性增益，写回按 `CC7 = gain×100`，**写回后要重新渲染**才进 MIDI。
- 「🧬 候选搜索」的适应度只衡量"更像参考曲"，**不衡量音乐性** →
  性格参数（律动/移调）必须人工确认；面板**默认不写回**。
- 指标只证明"像不像"，**好不好听只能靠耳朵**（与 `docs/UNMEASURABLE-SOLUTIONS.md` 一致）。
- 导入的 `.mid` 不进曲库（会话在 `%TEMP%`）；中间产物在 `%TEMP%\bgm-studio-audio\`，
  启动时按预算自动清理（>7 天删、总量压到 512MB）。

## 5. 这次任务的教训（写给下一个 agent）

1. **"能用脚本推的结论"和"一眼能看出来的结论"是两件事** ——
   卷帘看一眼就知道模板是单轨钢琴，我用脚本统计了三轮才得出同一结论。
2. **迭代速度决定试错次数**：6 分钟一轮让我"不敢多试"，
   所以整轮任务里我只改了十几版；3 秒一轮可以试几百版。
3. **"和参考曲同位置切换"是最强的判据**，优先于任何自动指标 ——
   `similarity.py` 六轴全是时间平均统计量，补完力度总分只动 0.1。
4. **studio 一直在跑**（`http://127.0.0.1:8765`，HTTP 200），
   不需要每次问"要不要启动" —— 先 `Invoke-WebRequest` 探一下，然后直接用。
