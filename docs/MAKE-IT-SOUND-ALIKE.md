# 扒带还原：把"乱"当作可测量的问题

> 场景：拿一首成品曲当"最佳案例"来学（原案例文档（已删 2026-09-24）），
> 用 Demucs 分六轨 + 逐轨扒谱重建一首"还原曲"。
> 用户反馈原话：**"没有像原曲一样很好控制乐器，有点乱"**。
> 这份文档记录：乱在哪、怎么量出来、怎么修、以及修的过程里踩的六个坑。

## 0. 一句话结论

"乱"不是音色问题，是**三处密度失控**：

| 症状 | 量化指标 | 原曲 | 修复前 | 修复后 |
|---|---|---|---|---|
| 鼓不跟段落呼吸 | 鼓活跃度（16 分格/小节） | **2.2 ~ 26.5**（随段波动） | 恒定 **29** | 逐小节 4 ~ 28 |
| 泛音被当独立音 | 同时发声音程里 12/19/24 半音族占比 | — | **25 ~ 31%** | 泛音剔除 |
| 主旋律全程缺失 | Melody 轨音数 | 每段都有 | **0**（bug） | 442 |
| 整体过采样 | 每小节音符数 | 27.3 | **43.6（1.60×）** | 按段对齐 |

结果：`similarity.py` 的 `variation` **26.7 → 79.9**、`timbre` **76.2 → 91.0**。

## 1. 怎么量"乱"（可复用的三个量）

音频起音数**不能**和 MIDI 音符数直接比 —— 混音里同时发声是**一个**起音，
而 MIDI 里是**多个**音符。这样比会得出"我密了 2.9 倍"的假结论（踩过）。
真正可比的是三个"结构量"：

1. **同时发声数（复音度）**：某时刻有几个音在响。原曲中位 6.8 / P75 8.0。
2. **同时发声的乐器数**：某时刻有几"轨"在响。原曲中位 3.6 / P75 3.9；
   超过 4~5 件就该怀疑"堆叠"。
3. **逐段每小节音符数**：把两个版本按 8 小节分段列表对比，
   看**疏密走势是否一致**（相关系数）+**倍数**（谁更满）。

第 3 条最有诊断力：`b35_seccmp.py` 一跑就能指出"哪一段比原曲满、满多少"。
修复前逐段倍数在 1.25 ~ **2.00×**，段间起伏 σ 9.3（原曲 4.4）——
**"满"是均匀地满，还额外放大了段间差**。

## 2. 三处失控的根因

### 2.1 鼓：用了全曲平均，等于"永远在 fill"

`perc_part` / `drum_grid` 是**一套** 16 格型铺全曲。
于是连原曲近乎无声的收尾段（鼓 RMS −34.8dB、活跃度 2.2 格/小节）也照敲 29 格。

修法：逐段逐小节从 drums 轨**实测**该段的真实格位（取该小节最强的 k 格，
k = 该小节有效格数），写进 `patterns.drum_grid.per_bar`。
引擎侧新增 `per_bar` 支持（`song_engine.build_events`）。

⚠ 不要"先把 8 小节平均成一节模板"——那会让每小节都变成"全段并集"，
等价于**每小节都在打 fill**，比固定网格还满。

### 2.2 扒谱过采样：泛音被当成独立音

CQT 峰值法的经典病：一个钢琴音的基频 + 二次谐波（+12）+ 十二度（+19）
在 −8dB 阈值内**全是局部峰**。实测同时发声音程里八度族占 25~31%。

修法：同轨同时刻（16 分格内）若某音是**更强的下方 12/19/24 半音音**的泛音，删之。
Bass 轨另有一种病：CREPE 在**相邻半音之间抖动**（同刻音程 87% 是 1 半音，
1059 音 / 998 事件）→ f0 先做 5 帧中值滤波 + 周期度门槛 0.35→0.5，
产出后再合并"邻接半音且前音 ≤0.5 拍"的碎片（1059 → 744 音）。

### 2.3 主旋律缺失：段内小节号 vs 全局小节号

`melody` 字段要的是**段内**小节号（引擎按 `(bar0 + b) * 4` 取时刻），
而扒旋律的脚本给的是**全局**小节号 → 时间落到曲子外，**Melody 轨 0 个音**。
（听感上就是"没人唱、糊成一片伴奏"，但代码不报错、指标也看不出来。）

顺带修了旋律提取本身：`track_to_notes` 只在 `onsets()` 检出的起音处取音，
而 `onsets` 的阈值（mean + 2.5σ + 0.15s 强制间隔）在密集混音里太保守，
331.9 秒只给出 **98 个音**。改成**逐帧音高轨迹法**（去掉 <0.13s 碎片 → 量化 16 分格
→ 同格取最高音 → 跨格同音高合并）得到 442 个音、26 段无空段。

## 3. 按段对齐密度（引擎能力）

`notes_extra` 现在支持增强格式：

```json
"notes_extra": {"Piano": {"notes": [[小节, 拍, 时值, 音高], ...],
                          "target": [每段目标音数, ...]}}
```

给了 `target` 就按该段**等间隔抽样**到目标值（不是每小节砍一刀——
那样会在小节边界留下规律的"缺口"）。没给就退回 `arr.density` 的固定上限。
扒带还原时用原曲转录的逐段音数当 target，密度曲线就跟着原曲走。

**实测（BGM35 还原曲）**：乐音轨统一取 `target = 0.63 × 当前逐段音数`
（0.63 来自实测倍数 43.6/27.3）→ 每小节 43.6 → **39.4**、逐段相关系数 0.76 → **0.82**；
主旋律不走这个缩放（它只有 1.00×，本来就是原曲量级）。
⚠ 注意 `b35_seccmp.py` 之类脚本若还读 **v1 转录**（未修过采样），
读数会系统性偏高（v1 比 v2 多 ~30%）——比"我 vs 原曲"时**两侧必须同版本**。

## 3.2 生成曲的四条听感问题：量法 + 修法（2026-09-18，19 首）

用户听完一批生成曲的四条反馈（**鼓像打字机 · 伴奏撞主奏 · 整首太平 · 旋律怪**）→ 逐条量清根因再动手。
**所有对照都拿仿写成品当基准**：`99_b35_remake/b35_remake.mid`（"更进一步"版，9 轨；`v5_source.mid` 是较早的 5 轨版，**读数不同别混用**）。

### 量法：五个数字就够（口径固定，别每次另造）

| 量什么 | 怎么算 | 仿写读数 | 我（旧） |
|---|---|---|---|
| 鼓密度 | **ch9** 音数 ÷ 小节数 | 18.99/小节 | 7.02 |
| 力度层次 | 不同 velocity 值的**个数** | **66 种**（主档 85 = 各段 `perc_vel_max`）| **13 种**（36/43/31/37 各 36 个 = **完全均匀**）|
| 落点铺开 | `int(round((s % 4) * 4)) % 16` 的非空格数（3/4 拍按拍号取模）| **16 格全满**、疏密差 2× | 只 **9 格**（基本只踩偶数格）|
| 撞主奏 | 伴奏轨与 Melody **时间重叠**（不只是同起点）且 \|Δpitch\| ≤ 2 | 41 处（Arp×Melody 24 + Hook×Melody 13）| 04：Hook74×Melody76 @4.3s |
| 段界 | `fade_out = median(pre) − median(p_edge)` · `fade_in = post − q_edge` · `jump = \|post − pre\|`（pre/post 取**段中部 30%~70%**）| — | 2 个边界 FAIL（2.7dB / 3.8dB，门 4）|

⚠ **别按"音高落在 35..82"猜打击轨** —— 会把 Hook/Piano 这些伴奏轨（音高恰好落在 GM 打击区）误判成鼓；**只认 channel 9**。
⚠ 逐段量：用户反馈**多数指向局部**（"前面有一点""12 秒左右"），先定位到段/小节再动；
但也有**整体判断**（"整首太平"）—— 那种按"全库扫描 + 逐段对照"处理，别再找"是哪一小节"。

### 修法一：鼓"像打字机" → 三件套 + 力度层次

三条一起做，**全在编配层**（不靠 CC7 / 电平）：
1. **三件套都出**（旧行为是"沙锤 + 两个点缀"）：八分踩镲骨架 + 底鼓（正拍强 / e 位弱）+ 小鼓（2、4 拍骨架 + a 位 + ghost）；
2. **落点铺到十六分**：按**哈希采样**落点（`hash(seed, i, g) < p`）→ 疏密自然不均；
3. **力度分档 + 确定性抖动**：`base ± spread`，抖动源是哈希 → 档数自然到 50~70（**不用随机数**，跑两次逐字节一致）。

**两条硬约束**（都是实测踩出来的）：
- **八分格必出**、不交给哈希 —— 这一档是 5–18kHz 的**唯一**来源，全概率化会出现整小节高频空洞；
- **时值 < 相邻十六分格距 0.25 拍** —— 密集化后同音高重叠会让 FluidSynth 配错 note-off、留下悬空 voice。

**一条防同质化**：`seed` 取**曲名哈希**。没有它，所有用同一档的曲子会共用**同一条**鼓型
—— 这正是当初"怎么都是这个"的病根。

**按档分设计，不搞一刀切**：`light` 侧棒 + 军鼓（轻档更柔）· `dance` 十六分铺开 + 四踩 ·
`orchestral` 定音鼓 + 三角铁微光（**不用鼓组**）· `waltz` **只踩第 1 拍**（守卫 `waltz_groove` 会拦"往第 3 拍加底鼓"）。
**结果**：19 首全部 16 格铺满、力度 39~76 档（旧 7~39）；orchestral 从 **3.44 音/小节**（比"打字机"还稀）→ 10.5~13.5。

### 修法二：伴奏撞主奏 → **和声内避让**（`patterns.avoid_lead`）

⚠ **先纠正一个直觉：撞音本身不是病**。仿写有 **498 处**"同起点 + 同音高"，比我们（02 是 32 处）**多得多**
—— 它撞的是**伴奏之间**（`Arp×Hook` 140、`Arp×Piano` 104、`Hook×Piano` 83）。
要修的是"**伴奏压在旋律的同音高/同音区上**"（主奏被自己的伴奏糊住）。

做法：把那个伴奏音**移到本和弦的另一个音级**（和声完全不变 ⇒ 和谐优先），
候选 = "**离主奏 ≥4 半音、又离原音最近**"的（跳幅最小）；和弦音里没有合适的就试 ±12。
**结果：全库 763 处 → 31 处**（残余是"和弦音与八度都移不开"的，已**低于仿写的 41 处**）。

### 修法三：段界硬切（`patterns.seg_in`）

⚠ 两个反直觉点（详见 `PITFALLS.md` 201）：
- **极安静段的段末留白造不出 4dB** —— 段中部本来就是谷底（17 的 B2 段中只有 −31.1dB），
  `section_gap` 开到 **3 拍**也只换来 2.7dB。**这种边界只能补段首那一侧**；
- **段末压"新起音的力度"没用**（我试的 0.15 小节窗口 ×0.45 幅度下读数一字未变）、**段首有效**
  —— 段末窗口的能量由**更早起音的长音**撑着，段首的音却全是新起的。
  ⚠ 别把这条读成"段末原理上无解"：我**只试了一种窗口与幅度**，换窗口（提前到 0.5 小节）、
  改时值、或减声部数都未必无效 —— 断言之前先试第二组参数。

做法：段首前 `seg_in` 拍（0.75 拍 ≈ 0.32s）力度从 **×0.15** 线性恢复；**不减声部**
（用户否掉过"段首 1 小节只剩 3 条轨"——空一下满一下，听着发乱）。**结果：全库 102 个边界 0 FAIL。**

### 一条元方法：动全局机制前，先"全库扫描"评估影响面

要动 `_RAMP`／段末这类**全局**机制时，先按判据把**全库**扫一遍再下刀
（本轮实测：102 个边界里只有 2 个 FAIL、"危险区（余量 <1.5dB）**0 个**" → 才敢加强退场）。
**别看单首下结论** —— 单首看不出这刀会把多少"刚好过线"的边界推出去。


## 4. 踩过的六个坑

1. **闭包里的循环变量**：`def _band(name): return v[i]` 里 `i` 在调用时已被
   后面的小节循环改掉 → 每段都读到同一小节。要用**默认参数固化** `def _band(name, _i=i)`。
2. **变量名覆盖**：`_ps = grid['per_section']` 之后 `_dg = _ps[i]`，
   第二段起 `_ps` 已是单段字典 → 全曲锁死在第一段。逐段/逐小节两套索引**必须分开命名**
   （最终改用**扁平 `per_bar`**，这类坑直接消失）。
3. **`gain_curve` 返回 dB 却当线性用**：低频被乘 −0.25（相位反转 + 衰减），
   整曲掉 12dB。返回线性增益，并**自检** `g=1` 时重建应逐样本相等。
4. **采样率口径**：96kHz 参考曲 vs 44.1kHz 渲染曲，固定 8192 点窗口在两边是
   85ms 与 186ms → 带能量不可比（假差 20dB）。统一到**较低**采样率，
   窗口按 `_nfft_for(sr)` 折算。
5. **两个工具两套口径**：`band_match.py` 的带能量与 `metrics.octave_bands`
   不是同一个函数。匹配了 A 的口径，B 只看得到部分改善
   （实测带差 2.82 → 2.47、`octave` 6.0 → 17.7）。**要用哪把尺子就用哪把尺子校准**。
6. **EQ 不是万能的**：`octave` 差得多时先看是不是"整条频谱倾斜"
   （那是混音平衡，EQ 正当）；若只有一两条带差得多，多半是编配/音色问题，
   硬填只会过拟合（踩过：800Hz 以上整体 +9dB 补"高频层被关掉"，
   `octave` 反而从 78 掉到 41）。

## 5. 还没验证的

- 修复后的音频**没有人耳确认**（`b35_remake.ogg`，334 秒）。
- `octave` 只回到 17.7：剩余带差集中在 20–40Hz(−4.8) 与 10–18kHz(−5.4)，
  两端各差 5dB 是**音源带宽**问题，不是 EQ 能补的。
- 逐段 target 抽样目前只用在 BGM35 还原曲上，没有在其他曲子上回归。
